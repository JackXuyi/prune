## 1. 结论先行

1. 【事实】**产品其实早就是开发者的工具，只有入口还不是。** 68 条白名单里 40 条 macOS 专属几乎全是开发缓存（Yarn/pnpm/Xcode/AI CLI）；内存口径为解决「进程真实占用」而生；端口反查回答的是「谁占着 3000」。但交付形态是 `.dmg` 双击 + 六个 tab，**没有 Homebrew，没有 JSON 契约，没有退出码规范**——开发者拿不到他习惯的接入点。
2. 【推断】**开发者客户的留存载体不是清理，是「日日要查的三件事」：端口、内存、网络。** 清理是一次性事件（毕业即用完），端口冲突是每天数次。当前端口能力被埋在第六个 tab，是本产品最大的一处价值错配。
3. 【事实】**MCP 只读面（8 个工具）是唯一无竞品对标的资产。** 竞品（DevCleaner / Vitals / Spookle）都在做「更好看的清理器」，没有人做「让 Agent 读开发机状态」。这条路的天花板取决于**契约稳定性**，不取决于工具数量。
4. 【推断】**ad-hoc 签名对开发者客户的伤害大于对普通用户。** 开发者遇到「已损坏，无法打开」不会右键绕过，会写 issue、发推、在 HN 评论区说一句——这正是开发者渠道的传播机制反向起作用（旧路线图 RK-9 只算了安装转化，没算声誉成本）。
5. 【事实】**产能是硬约束：** 3 人日/周 × 40 周 ≈ **120 人日**。本文三波合计 **110 人日（含 16.5 缓冲）**，任一里程碑延后按 §8.4 顺序裁，不挤关键路径。

## 2. 目标客户与主战场

### 2.1 三个细分，只打一个

| 细分 | 规模特征【估算】 | 主痛点 | 现有覆盖 | 判定 |
|---|---|---|---|---|
| **A. AI 辅助编码的独立开发者 / 小团队**（Node/TS 为主，macOS Apple Silicon，256–512 GB） | 主战场 | 磁盘红 + 依赖膨胀 + 本地服务端口混乱 | **最强**（npm/yarn/pnpm 重复存储、AI CLI 缓存、MCP） | **打** |
| B. iOS / Apple 平台开发者 | 次战场 | Xcode 残渣、模拟器、DerivedData | 强（M12/M28 深扫） | **守**（不新增投入，条目随版本补） |
| C. 后端 / 运维 / 基础设施 | 次战场 | 端口、连接、网络出口、局域网 | 中（端口/网络/局域网已备） | **借**（端口与网络增强顺带服务） |
| D. 家庭网络 / 泛用户 | — | NAS、路由器、设备发现 | 有（LAN 拓扑） | **放弃**（§12） |

**主战场判断依据**：① 白名单命中率最高；② 唯一能自然消费 MCP 的群体；③ 与「零遥测、无账号」不冲突（他们本来就不信任这类工具）；④ 传播路径清晰（GitHub / HN / V2EX / 掘金 / awesome-mac）。

### 2.2 客户画像（待访谈校准，标注为假设）

```
角色：独立开发者 / 3–8 人小团队的技术负责人
机器：MacBook Pro 14" 512 GB，常驻 Cursor + 3 个 dev server + Docker
日常：一天 6–10 次「起服务 / 查端口 / 看谁在吃内存」
现状替代：lsof -i :3000、活动监视器、ncdu、df -h、手写 shell 脚本
决策标准：装得上（brew install）→ 不添乱（零常驻、零账号）→ 能被脚本接（JSON/退出码）
【假设】他对「一键清理」的兴趣低于对「别让我手动拼 lsof」的兴趣
```

## 4. 开发者一天里的七个时刻 × 覆盖度

| 时刻 | 他要的回答 | 当前能力 | 覆盖 | 缺口 |
|---|---|---|---|---|
| 开机 / 磁盘红 | 这台机器还能腾出多少？ | 总览卡 + 分级清理 | ✅ | — |
| 起本地服务 | 3000 被谁占了，属于哪个项目？ | 端口 tab（第六个 tab） | 🟡 能查，找不到 | 入口前置 |
| 提交前 | 依赖体积有没有暴涨？ | 项目体检（只报当下） | 🟡 | 无趋势、无 CI 门禁 |
| 编译卡顿 / 风扇起飞 | 谁在吃 CPU / 内存？ | 应用卡 + 内存 tab | ✅ | — |
| 查内存泄漏 | 是真涨还是在骗我？ | 案件簿 + `mem_leaks` | ✅ | 差异化最强 |
| 拉不下来依赖 | DNS、代理还是站点？ | 网络诊断 + 站点五阶段 | 🟡 | 缺代理 / registry 维度 |
| 交接 / 提 issue | 怎么把机器状态给别人看？ | 复制 6 个数字 / 诊断 Markdown | 🟡 | 无统一报告导出 |

七格里 **2 格空白半格、1 格空白**。路线图的靶心就是把 🟡 变 ✅，而不是开拓第八格。

## 5. 定位重构

### 5.1 一句话

> **Prune 是开发机的可信读数层：磁盘、内存、端口、网络四个面，全部可核验、可脚本化、可交给 Agent 读。**

保留原有否定句（不是内存监控、不是通用清理器、没有一键优化），但把正向前缀从「浪费探测器」扩到「读数层」——因为**清理是读数的一个消费者，不是产品本体**。

### 5.2 必须直面的结构性错配

| 维度 | 现状 | 开发者期望 | 差距性质 |
|---|---|---|---|
| 获取 | `.dmg` 下载 + 拖入 Applications | `brew install --cask prune` | **阻断级**（开发者的第一道门） |
| 签名 | ad-hoc + 未公证 | 双击能开 | **阻断级**（且伤害声誉） |
| 输出 | 人读文本 / 部分 `--json` | 稳定 schema + 版本号 + 退出码 | **信任级**（写脚本的人只信契约） |
| 常驻 | GUI 常开 + 灵动岛 | 按需调用，能用就用完退出 | **体验级** |
| 集成 | MCP 需手写客户端配置 | 一条命令装好 | **转化级** |

这五项没有一项是「新功能」，全是**交付形态**。路线图 Wave 1 只做这五项，**不加任何探测能力**——这是本文最重要的一个取舍。

## 7. 优先级：RICE 评分卡

口径：`RICE = (Reach × Impact × Confidence) ÷ Effort`
Reach【估算】= 目标客户基数按 1,000 估，取「受此改进影响的人数」；Impact 按 3/2/1/0.5；Confidence 注明依据；Effort 为人日。

| 排序 | 候选 | Reach | Impact | Conf | Effort | RICE | 依据 |
|---|---|---|---|---|---|---|---|
| 1 | **签名 + 公证** | 700 | 3 | 0.9 | 1.5 | **1260** | 【事实】ad-hoc 已被 `spctl` 拒绝；开发者的第一道门 |
| 2 | **端口前置**（总览卡 + 菜单栏 + 冲突直达） | 700 | 1 | 0.8 | 3 | **187** | 【事实】端口已交付，仅入口位置问题 |
| 3 | **JSON 契约 v1**（schema 版本 + 退出码 + 全覆盖） | 600 | 2 | 0.9 | 6 | **180** | 【事实】写脚本的人只信契约 |
| 4 | **Homebrew tap + 安装脚本** | 700 | 1 | 0.9 | 4 | **158** | 开发者默认获取路径 |
| 5 | **`prune doctor`**（一键盘点） | 800 | 2 | 0.7 | 8 | **140** | 聚合适配，但价值取决于结论质量【假设】 |
| 6 | **`prune mcp install`** | 400 | 2 | 0.8 | 5 | **128** | 消除手写配置摩擦 |
| 7 | **项目账本 + `prune.toml`** | 500 | 2 | 0.6 | 10 | **60** | 有趋势才有「提交前」场景 |
| 8 | **MCP 8→12** | 400 | 1 | 0.8 | 6 | **53** | 边际收益递减，先稳再扩 |
| 9 | **`--emit-script`**（只打印不执行） | 250 | 1 | 0.5 | 3 | **42** | 违背「人才能删」需单独裁决（DP-4） |
| 10 | **`prune watch`**（按需守护） | 300 | 2 | 0.5 | 10 | **30** | 与「不做监控」定位冲突（DP-3） |
| 11 | **GitHub Action** | 200 | 2 | 0.6 | 8 | **30** | 需要项目账本先就位 |
| 12 | **VS Code 集成** | 400 | 1 | 0.5 | 12 | **17** | 成本最高的边缘体验 |

**读法**：前 6 项里 5 项是**交付形态**，只有 `doctor` 是新增能力。这解释了为什么 Wave 1 一个人日预算只有 34.5 天却能改变客户结构。**第 10、12 项在 Wave 2/3 有条件（门禁不达即砍）**。

## 8. 三波路线图

### 8.1 Wave 1「装得上、接得进」（2026-12 ～ 2027-02）

目标：一个开发者从听说到 `prune doctor` 出结论，**全程零文档、零右键、零手写配置**。

| 里程碑 | 内容 | 人日【估算】 | 验收口径（可判定） |
|---|---|---|---|
| **D-01 签名 + 公证**（DP-1 拍板后） | 购买年费 + workflow 公证分支 + 失败告警 | 1.5 | `spctl -a -vv` 判 `accepted`；公证失败 CI 必红 |
| **D-02 Homebrew** | tap 仓库 + cask（双架构自动选择）+ `prune-cli` 安装 + uninstall | 4 | 一台干净 Mac `brew install --cask` 后 `prune scan` 直接可用 |
| **D-03 契约 v1** | `schemaVersion` 字段、退出码表（0 正常 / 2 用法错 / 3 权限不足 / 4 探测失败）、`--json` 覆盖 7 命令 | 6 | 破坏性变更需主版本；CI 加 schema 快照对比 |
| **D-04 `prune doctor`** | 聚合磁盘/内存/端口/网络，输出「结论 + 证据 + 下一步」，人读与 JSON 双形态 | 8 | 30 秒内出结论；任一项读不到显示原因不显示 0 |
| **D-05 `prune mcp install`** | 写 Claude Desktop / Cursor / VS Code 配置，dry-run + 自动备份 | 5 | 安装后 Agent 首次调用成功率 100%（3 客户端各验一次） |
| **D-06 文档** | README 开发者入口重排、`docs/cli-reference.md`、契约兼容性门禁 | 4 | `pnpm check:docs` 覆盖新文档，MCP 对账门禁仍绿 |

**小计 28.5 人日 / 可用 36，缓冲 7.5。** 版本：`0.12.0`（D-01/02）→ `0.13.0`（D-03/04/05）。
**MCP 扩面（8→12）从 Wave 1 移出**——先冻结契约比先加工具值钱（RICE 第 8 项）。

### 8.2 Wave 2「从一次性清到日常读数」（2027-03 ～ 2027-05）

目标：让 Prune 出现在**每天至少一次**的路径上，而不是换机时才想起。

| 里程碑 | 内容 | 人日 | 验收口径 |
|---|---|---|---|
| **D-07 端口前置** | 总览加「冲突中」卡；菜单栏显示关注端口态；事件流点击直达该行 | 4 | 从菜单栏到「看到 pid + 项目目录」≤ 2 次点击 |
| **D-08 项目账本** | 项目级依赖体积/构建产物时间序列（90 天，落 SQLite），按项目聚合 | 9 | 每个项目能出「30 天涨了 X GB」且可回溯到具体目录 |
| **D-09 `prune.toml`** | 项目级配置：白名单增量、阈值、忽略项；校验失败显式提示不静默覆盖 | 5 | 损坏配置回落默认并告知；不存在配置时行为与 v0.13 一致 |
| **D-10 `prune watch`** | 按需守护（前台进程，Ctrl-C 即停）：端口冲突/磁盘水位/内存压力，输出 JSONL + 退出码，可选系统通知 | 8 | **不写 launchd/开机项**；退出后无残留进程 |
| **D-11 MCP 8→12 + 冻结** | 新增 `project_deps` / `build_artifacts` / `net_sites` / `swap_report`；工具 schema 冻结并写入文档 | 6 | 只读断言仍存（执行类动词按名拒绝）；门禁脚本覆盖 12 个 |
| **D-12 编辑器最小集成**（门禁 G2 通过才做） | VS Code 任务 + 状态栏只读读数 | 5 | 不注入命令、不写工作区文件 |

**小计 37 人日 / 可用 39，缓冲 2。** 版本：`0.14.0`（D-07/08）→ `0.15.0`（D-09/10）→ `0.16.0`（D-11/12）。

### 8.3 Wave 3「可交付、可协作」（2027-06 ～ 2027-08）

| 里程碑 | 内容 | 人日 | 验收口径 |
|---|---|---|---|
| **D-13 GitHub Action** | PR 评论依赖体积 delta（+X MB / −Y MB），可选阈值门禁 | 8 | 一个真实仓库接入并产出可读评论 |
| **D-14 报告导出** | `prune report --md/--json`：机器状态快照（磁盘/内存/端口/网络），供交接与 issue | 4 | 报告含时点、口径、不可读项原因 |
| **D-15 `--emit-script`**（DP-4 通过才做） | 只打印候选删除命令，**永不执行**，附白名单校验结果 | 3 | 单测断言无任何执行路径 |
| **D-16 1.0 收口** | 文档、契约迁移说明、发布门禁、`brew` 版本同步 | 6 | 1.0 定义 = 已签名 + 契约稳定 + 三入口（GUI/CLI/MCP）齐 |
| **D-17 开发者渠道** | HN / Reddit / V2EX / 掘金 各 1 次、awesome-mac 收录、brew analytics 读取 | 9 运营日 | 每次渠道动作带独立落地页（GEO 资产复用） |

**小计 30 人日 + 9 运营日 = 39 / 可用 39，零缓冲**——若 D-13 延后即砍 D-12 回补（§8.4）。

### 8.4 产能、裁单顺序与关键路径

**产能**：3 人日/周【假设，沿用旧路线图 A5】；2026-12～2027-08 约 40 周 ≈ 120 人日。三波合计 **96.5 工程日 + 9 运营日 + 4.5 缓冲**。

**裁单顺序（自上而下，一旦触发立即执行，不重新评估）**：
1. D-12 编辑器集成（5d，RICE 最低）
2. D-15 `--emit-script`（3d，条件项）
3. D-13 GitHub Action（8d，需前置账本，延后一季不损失）
4. D-11 MCP 扩面（6d，冻结契约比扩面重要，可只做冻结）

**关键路径**：`D-01 公证 → D-02 brew →（D-03 契约 → D-04 doctor → D-05 mcp install）→ D-07 端口前置 → D-08 项目账本 → D-13 Action → D-16 1.0`。
**可并行**：D-06 文档全程搭车；D-09 `prune.toml` 与 D-08 无代码冲突（配置层 vs 存储层）。

**与旧路线图的关系**：M3（分发入口）/M4（证据修复）/M-B（访谈）**继续有效但换对象**——落地页面向开发者渠道，对比页面向「lsof 组合拳」，访谈对象限定为主战场画像。M6（数据资产）并入 D-08 账本；M7/M8 的裁决时点顺延到 **2027-09-30**，判据见 §10。

## 10. 指标：零遥测下开发者客户怎么量

【事实】零遥测是产品承诺，不可为路线图破例。因此**所有指标必须在设备外可读，或由用户主动导出**。

| 指标 | 口径 | 性质 | 用途 |
|---|---|---|---|
| **brew 安装数** | tap analytics 周下载 | **硬读数** | 新客户获取（Wave 1 后才有） |
| **D1 下载数** | GitHub Release `download_count` | 硬读数 | 渠道对比（旧路线图已降级，仅趋势） |
| **D2 启动事件** | `latest.json` 请求数 | 硬读数 | GUI 活跃代理（【事实】CLI 不产生 D2） |
| **`doctor` 本地计数** | 用户主动「复制计数」征募（沿用 v0.10.0 机制） | 半硬 | 首次价值是否达成 |
| **二次调用率** | 征募样本中 7 天内 ≥3 次 `doctor`/`port` 的比例 | 半硬（样本 ≤100） | **留存主判据** |
| **issue 结构** | 「无法打开」类 / 需求类 / 缺陷类 比例 | 硬读数（人工归类） | 签名决策与文档质量 |
| **外部集成数** | 接入 Actions 的公开仓库数、MCP 客户端提及数 | 硬读数 | Wave 3 门禁 |

**不可测（永久，写进文档免得日后编数）**：真实 DAU/MAU、CLI 与 MCP 形态的采纳率、功能使用率、平台×留存交叉。

**门禁（不达标就改产品，不改指标）**：

| 门禁 | 时点 | 条件 | 不达动作 |
|---|---|---|---|
| **G1** | 2027-02-28 | brew 累计安装 ≥ 300 **且** D2 周值 ≥ 前 8 周均值 × 1.5 | 冻结 D-12，回修 `doctor` 结论质量 |
| **G2** | 2027-05-31 | 征募样本 ≥ 50，其中「7 天内 ≥3 次调用」≥ 30% | 停止扩 MCP 工具面，转做端口/内存的日常路径 |
| **G3** | 2027-08-31 | ≥3 个外部仓库接入 Action **或** ≥1 篇独立评测 | 1.0 推迟一季，不做团队方向 |

**北极星表述**：`周活跃开发机读数`（不可直测）→ 以 **二次调用率** 为唯一可用代理，D2/brew 只作趋势。**禁止**把 D2 直接写成「用户数」（旧路线图 §5.1 口径纪律继续有效）。

## 12. 明确不做（本三波）

| 项 | 理由 |
|---|---|
| 团队 SaaS / 云看板 / 账号体系 | 与「零遥测、无账号」根本冲突；单人无法承担运维与合规 |
| 自动清理 / Smart Trigger | 违背「不替人做主」；旧路线图已改判永不做 |
| 通用硬件监控（GPU / 温度 / 风扇 / 功耗） | README 已显式否认，做了等于换产品 |
| Windows GA | ≥50 人日且无上限；口径无等价物（Private Bytes ≠ footprint） |
| LAN 拓扑 / 宠物 / 年度报告二期 | 服务 D 类客户，与本文客户定义冲突（DP-5） |
| treemap / AI 会话追踪 / AI 余额 | 竞品红海，进入即用唯一资产换拥挤赛道 |
| 编辑器插件全功能化（侧边栏面板等） | 成本最高、收益最低（RICE 17）；只做任务与状态栏 |
| 任何形式遥测 / 暗桩埋点 | 永久红线 |
