# M20-b 拓扑视图视觉优化 · 方案

> 触发：实测截图（25 台设备）不可读——标签大面积叠压、满屏幽灵脉冲圈、全灰单调。
> 状态：已落地（0.8.2）。基线：docs/m20-lan-topology-spec.md，本方案只改视觉与布局，不动组件契约（props / 弹窗归属 / 拖拽机制均不变）。
>
> **落地时的方向修正（2026-11-12）**：§3 原本设计成「多环容量分配」，实测后发现同心环的根本问题不在容量，
> 而在**没有归属信息**——25 台均匀摊在环上，谁是网关的、谁连的是我，只能靠位置猜。
> 改为**轴向分层**（见 §10 修订），§3 的环版仅作历史记录保留。

## 1. 截图诊断（按严重级别）

| 级别 | 问题 | 代码级根因 |
|---|---|---|
| P0 | **标签大面积互相叠压**：顶部 5-6 台设备的「未知 + IP」完全糊成一团，左右两侧同样 | 单环容量溢出：25 台 ÷ 单环 → 角间距 ~14°，R≈200 时弧间距 ~50px，而标签宽 96px——**几何上必然叠**。±10° jitter 进一步恶化 |
| P0 | **满屏幽灵圈**：十几台设备身后挂着半透明大圆 | `animate-ping` 无上限：所有 `isNew` 同时脉冲（history 建基线后 10 分钟内二扫，大量设备命中新），且 25 个动画相位不同帧，截图上就是一圈圈鬼影 |
| P0 | **「未知」×N 噪声**：零信息量文字占满画面，真正唯一的身份 IP 反而挤在第二行 | 标签策略照搬卡片（hostname ?? kindLabel），没考虑拓扑场景「未知」占了 80% |
| P1 | **全灰单调**：所有节点一个色，与设备卡的域色系统完全脱节 | 拓扑自写了 `bg-white/[0.05]` 统一灰底，没复用 LanDeviceCard 的 `tileTone` 域色 |
| P1 | **大「?」图标 ×N**：未知设备的大问号 tile 视觉权重过高 | unknown kind 与普通设备同尺寸同构 |
| P1 | **边穿过标签**：网关辐射线压着本机/网关标签和相邻节点文字 | 线从中心画到中心 + 标签常显，层上打架 |
| P2 | hostname 长串中截难看（`HP7C4D8E57867F7…`） | truncate 直截尾部 |
| P2 | 离线与在线混在同一环，重点不清 | 布局未区分在线/离线 |

## 3. A · 布局 v2：多环容量分配（⚠️ 已被 §10 轴向分层取代，仅存档）

```
function layout2(devices, w, h):
  // 环容量由最小弧间距反推：相邻节点中心弧距 ≥ SPACING(72px)
  capacity(R) = floor(2πR / SPACING)
  R1 = clamp(120, min(w,h)/2 − 96, 240)

  // 分配顺序：在线普通设备按 kind 分组（同类型聚簇，域色自然成弧带）
  //   → 内环 R1 装满 → 溢出进 R1+64 → 再溢出 R1+128（最多 3 环）
  // 离线设备一律最外环（faint ring），不挤占在线空间
  // jitter 收敛到 ±6°：仍打散机械感，不再制造叠压
  // 本机：网关正下方 56px（更贴身，虚线圈不再撞环上标签）
```

- 25 台在线实测：R1≈200 容量 17 → 内环 17 + 外环 8，两环消除叠压；
- 同 kind 聚簇后域色在环上成段分布，扫一眼就能看出「这一段是手机/这一段是 IoT」。

## 4. B · 标签策略 v2：默认极简，hover 展开

| 状态 | 显示 |
|---|---|
| 默认 | 单行 9.5px mono IP（宽 70px，`opacity 0.45`）。**不再渲染「未知」**——unknown 的身份就是 IP，kind 由 tile 域色表达 |
| hover | 该节点展开双行：hostname/类型词（`text-ink` 提亮）+ IP；其余节点标签降到 `opacity 0.2` |
| hostname 截断 | 中段省略（保留头尾各 5 字符：`HP7C4…67F7`），比尾截更有辨识度 |

标签从「每节点两行常显」减到「每节点一行半透明」，画布文字量降 ~70%。

## 5. C · 节点 v2

| 项 | 现状 | 改为 |
|---|---|---|
| 域色 | 全灰 `bg-white/[0.05]` | **复用 `tileTone`**（从 LanDeviceCard 导出或抽到 `lan/tileTone.ts` 共用）：路由/本机/网关 accent、电脑/手机/平板 info、NAS 青、IoT 家族紫、未知 chip——拓扑与卡片视觉同源 |
| unknown 设备 | 46px tile + 大「?」图标 | **20px 实心小灰点**（`bg-chip ring-1 ring-hairline`），无图标——有身份的设备才配图标 |
| 尺寸 | 46 / 54px | 38 / 46px（25 台密度下的合理权重） |
| 新设备 | ping + badge | 见 §6 |

## 6. D · 脉冲收敛

```
pulseTarget = isNew 设备中 firstSeen 最大的那一台（刚入网的新面孔）
其余 isNew   → 静态 accent ring-2 ring-accent/50 + 「新」badge（不动画）
pulseTarget  → ping 脉冲保留，但扩散范围限制在 tile 尺寸（inset-0 → scale 1.4 内收）
```

画布上同时最多 1 个动画——「刚来的那台」获得全部注意力，其余新设备仍可识别。

## 7. E+F · 边与离线

- 边基色 opacity `0.15 → 0.10`，hover 相关边才提亮（现有高亮逻辑保留）；
- 本机 offset 84 → 56px；
- 离线设备统一最外环 + 现有置灰虚线不变——内环永远是在线主战场。

## 9. 待确认（已裁决）

1. 标签默认态 → **极简 IP 单行、opacity 0.85**。完全隐藏只剩一圈圆点，25 台时无法区分任何两台；单行 IP 是「最低限度可识别」的边界。
2. 重排与拖拽记忆 → **布局上线即全量重排一次，拖过的位置保留**。实现上按 ip 记 `dragged` 集合：只有用户亲手拖过的 key 才保住旧坐标，其余跟布局走——这样新设备入网时能落进空位，而不是叠在上一个位置。

## 10. 落地修订：轴向分层（取代 §3 多环）

### 10.1 为什么换掉同心环

环版跑通后（25 台 fixture，1280 宽）实测仍有两个问题，且都不是「容量」能解决的：

| 问题 | 根因 |
|---|---|
| 环上设备的归属看不出来 | 环只有一个维度（半径），所有设备是平权的。谁连网关、谁连我，环上没有任何表达——而这恰恰是拓扑图唯一的用处 |
| 边必须画成网关→全量的星形 | 因为设备都在环上，边只能从中心辐射。25 条辐射线穿过别人的标签，读起来像噪点 |
| 外环还会撞标签 | 环间距 78 时外环节点顶到内环标签；再放大就要加高画布，25 台时画布 ~600px 且大半是空的 |

### 10.2 新布局：一条脊柱 + 两侧分支

```
连我的设备1-N  ——  本机  ——  网关  ——  连网关的设备1-N
```

语义就是一棵树，网关是根：

- **网关居中**（x 恒为画布中点，y 为画布中点）；
- **本机**挂在网关左侧固定 150px 处，脊柱上那一段就是「本机—网关」这条边；
- **连我的设备**（`inbound.length > 0`）排在**本机更外侧**，标签挂在节点左边；
- **其余设备**排在**网关右侧**，按列堆叠，标签挂在节点右边；
- 没有网关时本机顶替中心位，其余设备一律挂它右侧（没有再分组的依据）。

边也跟着变成三条规则，不再有星形：`网关—本机`、`网关—连网关的设备`、`本机—连我的设备`。
边从节点圆边界起步（两端各退一个半径），不从圆心穿出。

### 10.3 拟合规则（确定性，无仿真）

| 参数 | 值 | 说明 |
|---|---|---|
| 每列台数 | 4 → 10 递增试 | 排不下就加高画布，而不是挤压横向 |
| 列宽 | 140 → 124 试 | 要容下「圆 19 + 间距 6 + 标签 80 = 105」 |
| 判据 | `SPINE_GAP + cw*(cols-0.5) + LABEL_SPAN ≤ w/2 − MARGIN` | 最外一列的**标签右沿**也要落在画布内 |
| 行距 | 58 | 标签在侧面，纵向只需容下两个圆 |

25 台 @1182 宽实测：右侧 3 列（7/7/6）+ 左侧 1 列（3）+ 脊柱 2 台，画布 1182×528，**零越界零叠压**。

### 10.4 标签与边的分工（这一版才真正不打架）

| 项 | 处理 | 原因 |
|---|---|---|
| 标签位置 | 挂在**背向脊柱**的一侧 | 边从脊柱那侧进来；标签放同侧必然被穿 |
| 标签宽度 | 80（13 字符 IP 实测 74.4px） | 74 会触发省略号，IP 被截成 `192.168.1.2…` 就没法用了 |
| 默认态 | 只有一行 IP，opacity 0.85 | 名称进 hover——「未知」这类零信息量文字不再占画面 |
| 文字光晕 | `text-shadow` 用画布底色打三圈 | 网格密度下任何直连边都会斜穿别人的标签，靠底色光晕把线「抠掉」，比给每个标签加实心底板轻 |
| 边 | 0.35（hover 1.0，非相关 0.18） | 文字必须是主角；线只做暗示 |

## 12. 极端密度兜底修正（45 台实测，0.8.3）

§11 原把「>40 台」标为 ⚠️ 未验证，理由是兜底是「10 台/列硬排」。补造 fixture（45 台：网关 + 本机 + 5 台连了我 + 38 台其余）实测，发现兜底不只是「可能拥挤」，而是**确定会裁掉 IP**：

| 现象 | 根因 | 修法 |
|---|---|---|
| 最右列 IP 只剩 `192.168.1…`，最左列只剩 `168.1.54` | 兜底分支先用「10 台/列」反推列数（38 台 → 4 列），再用这个列数硬排，**没有回头校验宽度**：4 列时最右标签右沿 ~1101+105 = 1206 > 1182，被 `overflow-hidden` 裁掉 | 兜底改为**宽度硬约束优先**：列数取「标签右沿仍落在画布内」的最大值（`c ≤ (half − base − LABEL_SPAN)/colW + 0.5`），行数不设上限——装不下就加高画布（页面可滚），宁可画布变长也不能把 IP 裁成省略号 |

实测：45 台 @1182 宽 → 右侧 3 列（13/13/12）+ 左侧 2 列（3/2），画布 876 高，标签零裁切；25 台回归不受影响（h=528 与 §11 记录一致）。

**取舍**：极端密度下画布会明显变长（45 台 ≈ 876px，需滚动），这是刻意的——IP 是拓扑视图里唯一的身份信息，裁掉就等于这台设备不可识别；拥挤但完整的图，比「看起来刚好一屏」的图有用。
