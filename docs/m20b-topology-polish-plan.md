# M20-b 拓扑视图视觉优化 · 方案

> 触发：实测截图（25 台设备）不可读——标签大面积叠压、满屏幽灵脉冲圈、全灰单调。
> 状态：方案评审中（未开工）。基线：docs/m20-lan-topology-spec.md，本方案只改视觉与布局，不动组件契约（props / 弹窗归属 / 拖拽机制均不变）。

## 1. 截图诊断（按严重级别）

| 级别 | 问题 | 代码级根因 |
|---|---|---|
| P0 | **标签大面积互相叠压**：顶部 5-6 台设备的「未知 + IP」完全糊成一团，左右两侧同样 | 单环容量溢出：25 台 ÷ 单环 → 角间距 ~14°，R≈200 时弧间距 ~50px，而标签宽 96px——**几何上必然叠**。±10° jitter 进一步恶化 |
| P0 | **满屏幽灵圈**：十几台设备身后挂着半透明大圆 | `animate-ping` 无上限：所有 `isNew` 同时脉冲（history 建基线后 10 分钟内二扫，大量设备命中新），且 25 个动画相位不同帧，截图上就是一圈圈鬼影 |
| P0 | **「未知」×N 噪声**：零信息量文字占满画面，真正唯一的身份 IP 反而挤在第二行 | 标签策略照搬卡片（hostname ?? kindLabel），没考虑拓扑场景「未知」占了 80% |
| P1 | **全灰单调**：所有节点一个色，与设备卡的域色系统完全脱节 | 拓扑自写了 `bg-white/[0.05]` 统一灰底，没复用 LanDeviceCard 的 `tileTone` 域色 |
| P1 | **大「?」图标 ×N**：未知设备的大问号 tile 视觉权重过高 | unknown kind 与普通设备同尺寸同构 |
| P1 | **边穿过标签**：网关辐射线压着本机/网关标签和相邻节点文字 | 线从中心画到中心 + 标签常显，层上打架 |
| P2 | hostname 长串中截难看（`HP7C4D8E57867F7…`） | truncate 直截尾部 |
| P2 | 离线与在线混在同一环，重点不清 | 布局未区分在线/离线 |

## 2. 优化方案总览

| # | 改动 | 解决 |
|---|---|---|
| A | **布局 v2：多环容量分配**（确定性，无仿真） | P0 叠压 |
| B | **标签策略 v2：默认极简，hover 展开** | P0 噪声 / P0 叠压 |
| C | **节点 v2：复用 tileTone 域色 + unknown 小灰点 + 缩号** | P1 单调 / P1 问号 |
| D | **脉冲收敛：只脉冲最新一台** | P0 幽灵圈 |
| E | **边弱化 + 本机贴身** | P1 穿线 |
| F | 离线设备固定最外环 | P2 |

## 3. A · 布局 v2：多环容量分配

```
function layout2(devices, w, h):
  // 环容量由最小弧间距反推：相邻节点中心弧距 ≥ SPACING(72px)
  capacity(R) = floor(2πR / SPACING)
  R1 = clamp(120, min(w,h)/2 − 96, 240)

  // 分配顺序：在线普通设备按 kind 分组（同类型聚簇，域色自然成弧带）
  //   → 内环 R1 装满 → 溢出进 R1+64 → 再溢出 R1+128（最多 3 环）
  // 离线设备一律最外环（faint ring），不挤占在线空间
  // jitter 收敛到 ±6°：仍打散机械感，不再制造叠压
  // 本机：网关正下方 56px（更贴身，虚线圈不再撞环上标签）
```

- 25 台在线实测：R1≈200 容量 17 → 内环 17 + 外环 8，两环消除叠压；
- 同 kind 聚簇后域色在环上成段分布，扫一眼就能看出「这一段是手机/这一段是 IoT」。

## 4. B · 标签策略 v2：默认极简，hover 展开

| 状态 | 显示 |
|---|---|
| 默认 | 单行 9.5px mono IP（宽 70px，`opacity 0.45`）。**不再渲染「未知」**——unknown 的身份就是 IP，kind 由 tile 域色表达 |
| hover | 该节点展开双行：hostname/类型词（`text-ink` 提亮）+ IP；其余节点标签降到 `opacity 0.2` |
| hostname 截断 | 中段省略（保留头尾各 5 字符：`HP7C4…67F7`），比尾截更有辨识度 |

标签从「每节点两行常显」减到「每节点一行半透明」，画布文字量降 ~70%。

## 5. C · 节点 v2

| 项 | 现状 | 改为 |
|---|---|---|
| 域色 | 全灰 `bg-white/[0.05]` | **复用 `tileTone`**（从 LanDeviceCard 导出或抽到 `lan/tileTone.ts` 共用）：路由/本机/网关 accent、电脑/手机/平板 info、NAS 青、IoT 家族紫、未知 chip——拓扑与卡片视觉同源 |
| unknown 设备 | 46px tile + 大「?」图标 | **20px 实心小灰点**（`bg-chip ring-1 ring-hairline`），无图标——有身份的设备才配图标 |
| 尺寸 | 46 / 54px | 38 / 46px（25 台密度下的合理权重） |
| 新设备 | ping + badge | 见 §6 |

## 6. D · 脉冲收敛

```
pulseTarget = isNew 设备中 firstSeen 最大的那一台（刚入网的新面孔）
其余 isNew   → 静态 accent ring-2 ring-accent/50 + 「新」badge（不动画）
pulseTarget  → ping 脉冲保留，但扩散范围限制在 tile 尺寸（inset-0 → scale 1.4 内收）
```

画布上同时最多 1 个动画——「刚来的那台」获得全部注意力，其余新设备仍可识别。

## 7. E+F · 边与离线

- 边基色 opacity `0.15 → 0.10`，hover 相关边才提亮（现有高亮逻辑保留）；
- 本机 offset 84 → 56px；
- 离线设备统一最外环 + 现有置灰虚线不变——内环永远是在线主战场。

## 8. 实施拆分

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 | 布局 v2（多环容量 + kind 聚簇 + 离线外环）+ tileTone 抽出共用 | 25 台实测截图走查：**零标签叠压** |
| P2 | 标签 v2 + unknown 小灰点 + 节点缩号 | 默认态画布文字量减 ~70%；hover 展开正常 |
| P3 | 脉冲收敛 + 边弱化 + 本机贴身 | 同屏最多 1 个动画 |
| P4 | 门禁（tsc / check:i18n / build）+ CHANGELOG + bump patch | 全绿，2 commit |

## 9. 待确认

1. 标签默认态选哪种：**极简 IP 单行**（方案现状，推荐——信息密度最低但可读）vs **完全隐藏 + hover 才显示**（更干净，但一眼看不出谁是谁）？
2. kind 聚簇会改变现有设备的位置（重排一次），拖过的位置是否保留？（推荐：布局 v2 上线即全量重排一次，拖拽记忆照旧）
