# Prune UI v4 重设计方案「Quiet Cockpit · 静谧驾驶舱」

## 一、文档信息

| 项 | 值 |
|------|------|
| 版本 | v4.0（设计方案，待确认后实施） |
| 基线 | UX v3 方案 A 已落地现状（6 tab + 可回收主卡 + statsReadout 同源读数层） |
| 配套样式稿 | `docs/ui-style-v3.html`（10 节全量 mock：token / 总览 / 应用 / 网络 / 端口 / 内存 / 存储 / 菜单栏面板 / 灵动岛双态 / 设置弹层 + 空态） |
| 设计目标 | 简洁 · 有趣 · 科技感 —— **多用图表和图标，少用文字** |
| 红线（不变） | 假事实红线、口径透明、只读呈现 + 破坏性操作集中、可见性门控、下钻有来有回 |

> 一句话定位转变：从「信息面板」（文字 + 数字堆叠）→「驾驶舱仪表」（图形 + 大数字 + 微动效）。所有读数、口径、门控逻辑复用现有 statsReadout 层，本方案只动**呈现层与导航层**。

## 二、现状诊断（为什么重设计）

| 编号 | 问题 | 级别 | 依据 |
|------|------|------|------|
| V-1 | 文字密度过高：卡片内 caption、hint、口径说明全部平铺显示，扫一眼抓不到主数字 | P0 | StatsBoard / MainWindow Overview 实测 |
| V-2 | 图表形态单一：几乎全是横向 MeterBar，缺「环形仪表、面积走势、点阵图」等有科技感的形态 | P1 | charts/ 目录仅 4 个条形构件 |
| V-3 | 导航纯文字 tab，图标语言缺席；6 个 tab 的语义靠文字识别，慢 | P1 | Tabs 组件 |
| V-4 | 缺乏「有趣」：无数字滚动、无微动效反馈，工具感重、产品感弱 | P2 | 全局 |
| V-5 | 空态/扫描态是一行灰字，缺乏品牌温度（剪刀 IP 没有进入页面） | P2 | ReclaimBoard 空态 |

## 三、设计方向：三条硬原则

### 3.1 图形优先（Chart-first）

每个读数固定为四件套：**图标 + 大数字 + 微图表 + hover 口径**。文字降级两层：

| 层级 | 呈现方式 | 示例 |
|------|----------|------|
| L1 常显 | 图标 + 主数字（28–36px）+ 微图表 | 💾 54.9 GB + 四段环 |
| L2 hover | 口径 caption（tooltip，1 句） | 「footprint 口径 · 含换出量」 |
| L3 下钻 | 明细页内完整文字说明 | 进程详情页 |

### 3.2 颜色即语义（Color-as-Language）

每个域一个专属色，全站贯穿（图标 / 图表 / 导航选中态 / 灵动岛联动）：

| 域 | 色 | 语义 |
|----|----|------|
| 可回收/存储 | accent 绿 `#34d399` | 行动 |
| 内存 | info 蓝 `#6aa9ff` | 冷静监控 |
| CPU | 紫 `#a78bfa` | 算力 |
| 网络 | 青 `#22d3ee` | 流动 |
| 端口 | 琥珀 `#f5b74a` | 警觉 |
| 危险 | 红 `#f0705f` | 停 |

### 3.3 微动效叙事（Alive, not noisy）

| 动效 | 场景 | 时长 |
|------|------|------|
| 数字滚动（count-up） | 主数字变化 | 400ms ease-out |
| 环形仪表描边动画 | 首次进入 tab | 600ms |
| 扫描光扫过卡片 | 磁盘扫描进行中 | 循环 2s |
| 呼吸灯 | 泄漏嫌疑卡 | 2.4s 循环 |
| 完成庆祝 | 清理完成（回收 GB 飘出 +N） | 1.2s 一次性 |
| 卡片抬升 + 发光 | hover | 150ms |

全部动效尊重 `prefers-reduced-motion`（现有 index.css 已有先例）。

## 四、信息架构：6 tab 不变，导航形态重构

### 4.1 左侧图标导航栏（Icon Rail）

顶部文字 tab → **左侧 56px 图标栏**：

- 图标 20px + 选中态左侧 2px 发光竖条 + 域色
- hover 显示 tooltip 文字（「总览 · 可回收 + 本机资源」）
- ⌘1–6 快捷键保留；底部固定「设置」齿轮
- 收益：960px 宽度全部让给内容；图标先于文字被识别；科技感底座

### 4.2 页面结构统一为「驾驶舱三段式」

```
┌─ rail ─┬──────────────────────────────┐
│ 🏠     │  Hero 区：1 个主仪表（全宽）   │
│ ⚙应用  │──────────────────────────────│
│ 🧠     │  Grid 区：4–6 张域卡（微图表） │
│ 💾     │──────────────────────────────│
│ 🌐     │  Detail 区：该域榜单/明细      │
│ 🔌     │                              │
│ ⚡设置  │                              │
└────────┴──────────────────────────────┘
```

## 五、六屏重设计要点

### 5.1 总览（旗舰屏）

- **Hero：可回收环形仪表**。外环四段（L1 绿 / L2 绿 / L3 黄 / L4 红）按 GB 占比分配弧长，中心 44px 大数字「54.9 GB」+ 小字「可回收」。未扫描时环为虚线空轨 + 「立即扫描」按钮，绝不显示 0
- **六张域卡**：内存（已用环 + swap 阈值微条）、CPU（10 min 面积走势）、硬盘（已用/总量细条）、端口（点阵图：每个监听端口一个点，按 exposure 着色）、下载/上传（双向面积走势合并一卡，↓青 ↑紫）
- 点击任意卡 → 对应 tab（下钻映射沿用 UX v3 §4.2）

### 5.2 应用

- 应用卡 → **横向排行榜**（icon + 应用名 + CPU/内存双 mini-bar + 网速火花线），Top 12
- 排序器收敛为 6 个图标 chip（进程/CPU/内存/磁盘/端口/网速），选中即发光
- 卡片行 hover 右滑露出「端口数」徽标

### 5.3 内存

- 右栏顶部：**内存压力环形仪表**（绿/黄/红三色弧）+ 已用大数字
- swap：阈值仪表条保留（75/90 刻度），升级为带渐变填充的科技条
- 左栏家族列表：每行加**内存占比迷你条**（宽度即占比），文字弱化
- 换出受害者：红橙渐变 bar list

### 5.4 存储

- Hero：卷容量 **细环形仪表**（剩余空间）+ 可回收大数字
- L1–L4：四张横向分级卡（色块 + GB + 一条占比条），点击展开 dry-run 清单
- 清理完成：+N GB 飘字庆祝动效

### 5.5 网络

- Hero：**双向实时面积图**（↓青 / ↑紫 双层，1s 心跳），峰值虚线标注
- 7 日流量：迷你柱状图（今天高亮）
- 按应用 Top 8：横向条形榜（青色渐变）
- 诊断：三层探测结果改为**三段进度轨道**（DNS→网关→出口，逐段点亮，耗时标注在节点旁）

### 5.6 端口

- Hero：**端口点阵仪表盘**——监听端口按分组排成点阵，绿=关注层、琥珀=对外、灰=其他，hover 出 tooltip（端口 + 进程）
- 反查列表保留搜索 + 表格，行内进程名列加图标

### 全局

- 空态统一插画：剪刀 IP 线稿 + 一句话（如「还没有可回收的东西，很干净 ✂️」）
- 标题栏精简：Logo + 域名标题 + 刷新（图标化）+ 设置移入 rail

## 六、Design Tokens 增量（在现有 @theme 上追加）

```css
--glow-accent: 0 0 24px rgba(52, 211, 153, 0.25);      /* 卡片 hover 发光 */
--glass: rgba(255, 255, 255, 0.04);                     /* 玻璃卡面 */
--glass-border: rgba(255, 255, 255, 0.07);
--domain-mem: #6aa9ff;  --domain-cpu: #a78bfa;
--domain-net: #22d3ee;  --domain-port: #f5b74a;
--num-hero: 40px;  --num-card: 28px;                    /* 大数字字号 */
--radius-card: 14px;  --radius-hero: 18px;
--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1);
```

新增图表构件（charts/）：`RingGauge`（环形）、`AreaChart`（面积走势）、`DotMatrix`（点阵）、`TrackProgress`（分段轨道）、`CountUp`（数字滚动）。全部纯 SVG + CSS，零依赖。

## 七、实施拆解（确认后执行）
