# Prune · 托盘动态图标：剪刀快慢 = CPU 繁忙程度（M6）方案

> 状态：已实施（2026-11-03，T0–T3 随 M5-C0 落地）· 前置：`docs/m5-cpu-plan.md` 的 **C0 数据层**（整机 `cpu.usage` 管道）必须先落地
> 一句话：菜单栏剪刀图标的**开合动画速度**编码 CPU 繁忙程度——闲时完全静止，忙时越剪越快。图标本身不显示数字、不变颜色，只编码一个维度：**快慢**。

## 0. 结论先行

1. **实现方式**：预生成 4 帧剪刀开合图（闭合 → 半开 → 全开 → 半开），按 CPU 档位以不同帧率循环播放；帧图编译期内嵌（`include_bytes!`），运行时只做 `set_icon` 换帧，不涉及实时绘图。
2. **关键 API**（已在 tauri 2.11.5 源码确认）：macOS 必须用 `set_icon_with_as_template(icon, true)`（`tauri/src/tray/mod.rs:577`）——tauri 自己的文档写明：先 `set_icon` 再 `set_icon_as_template` 会**渲染两次导致可见闪烁**，这个组合 API 就是为「换帧不闪」准备的；Windows/Linux 自动降级为 `set_icon`。
3. **档位映射**（10 s 一档，与内存采样同频）：`<10%` 静止 → `10–40%` 慢（2 fps）→ `40–70%` 中（5 fps）→ `>70%` 快（10 fps）。**读不到 CPU = 永远静止**，绝不拿未知值驱动动画。
4. **成本**：动画是自适应定时器——空闲档不跑循环（只在每次 10 s 快照轮醒来评估一次），忙档最高 10 fps 的 `set_icon` 也是主线程上的一次 NSImage 赋值，可忽略。
5. 四阶段 T0–T3 约 1 人天，依赖 M5-C0（0.5 天）先行。

## 1. 需求理解

| 点 | 结论 |
|---|---|
| 用户要什么 | 不点开面板，扫一眼菜单栏就知道「机器现在忙不忙」 |
| 为什么用剪刀 | Prune 的品牌符号就是剪刀；「剪得越快 = CPU 越忙」是自解释的隐喻，不需要学习 |
| 编码维度 | **只有快慢**。不编码颜色（macOS 模板图必须是单色，且彩色会破坏菜单栏观感）、不编码数字（菜单栏塞数字违反克制原则） |
| 与产品定位的关系 | 这不是退化成硬件监控——它是「浪费探测」的环境指示器：**闲 = 安心，快 = 该打开面板看看是谁**。定位修订随 M5 一起改 README，本方案不重复 |

## 3. 档位与动画设计

### 3.1 档位映射（快慢编码）

| 档 | 整机 CPU（近 10 s 均值） | 帧率 | 一个开合周期 | 观感 |
|---|---|---|---|---|
| 0 · 静止 | `<10%` 或 `null` | 不播放（静止在闭合帧） | — | 安心 |
| 1 · 慢 | `10–40%` | 2 fps | 2.0 s | 有事在跑 |
| 2 · 中 | `40–70%` | 5 fps | 0.8 s | 明显在忙 |
| 3 · 快 | `>70%` | 10 fps | 0.4 s | 火力全开，该点开看看 |

- 帧序列 `f0 → f1 → f2 → f3 → f2 → f1`（6 拍一个周期，往返开合，避免「跳变回闭合」的生硬感）。
- 阈值边界抖动：档位判定每 10 s 一次（采样粒度决定），本身就是低频切换，不加迟滞带；实测若观察到档位来回跳，再加 ±5% 迟滞（记入 §8 风险）。

### 3.2 帧图设计

```
f0 闭合          f1 半开          f2 全开          f3 半开（=f1 镜像节拍）
   \  /             \  /             \    /          
    \/               /\              /  \             
────✂────        ────✂────       ────✂────        （刀刃绕轴心 ±0°/±18°/±36°）
```

- 基底沿用现有 `tray.png` 的剪刀造型与 48×48 画布，**只转刀刃角度**，避免换帧时图标「重心跳动」。
- macOS：黑色 + alpha 的模板帧 ×4（系统自动适配深浅色菜单栏，沿用现有机制）。
- Windows：同参数渲染**品牌色帧** ×4（W3 的教训：深色任务栏下黑色模板图不可见）。
- 产出走脚本 `scripts/gen-tray-frames.mjs`：参数化 SVG（刀刃角度入参）→ sharp 渲染两套 PNG → `src-tauri/icons/tray-anim/{macos,win}/f{0..3}.png`。脚本可重跑，资产不手工修图。

### 3.3 tooltip 顺带升级（T2 顺手项，不占新预算）

每次 10 s 快照轮把 tooltip 从静态 `Prune` 更新为 `Prune · CPU 12%`——hover 有精确数字，图标只给量感，两个通道各司其职。

## 4. 模块设计（T0 → T3）

### 4.1 T0 · CPU 数据管道对齐（依赖 M5-C0，~0.1 天）

- 确认 `MemSnapshot.cpu.usage`（`Option<CpuInfo>`）已可用；若 M5-C0 未合入，本方案全部阻塞。
- `MemState` 对 tray 层只暴露一个只读入口：`app.state::<Arc<MemState>>()` 读 `snapshot`。**不新增 IPC、不新增事件**——动画驱动直接读共享状态，避免事件风暴。

### 4.2 T1 · 帧资产生成（~0.3 天）

| 项 | 内容 |
|---|---|
| `scripts/gen-tray-frames.mjs` | 读 `assets/tray-glyph.svg`（从现有 tray.png 逆向或重绘），4 个角度入参渲染 macOS 黑帧；同 SVG 换品牌色渲染 Windows 帧；sharp 输出 48×48（macOS）/ 32×32（Windows） |
| 资产 | `src-tauri/icons/tray-anim/macos/f{0..3}.png`、`.../win/f{0..3}.png` |
| 验收 | 脚本重跑产物 diff 为空（确定性渲染）；4 帧肉眼检查刀刃角度递进、画布无位移 |

### 4.3 T2 · 动画驱动（~0.3 天）

`src-tauri/src/tray.rs` 新增（不新建模块，与定位/点击同文件）：

```rust
/// 帧图编译期内嵌；Image<'static> 启动时构建一次
static FRAMES_MACOS: [Image<'static>; 4] = ...;  // include_bytes! ×4
static FRAMES_WIN: [Image<'static>; 4] = ...;

/// 档位 → (帧间隔 ms, 是否播放)；None = CPU 未知
fn tier_of(usage: Option<f32>) -> Option<Tier> { ... }

pub async fn run_anim(app: AppHandle) {
    loop {
        let usage = /* 读 MemState.snapshot.cpu */;
        match tier_of(usage) {
            None | Some(Tier::Idle) => {
                // 静止：切到 f0，睡到下一个 10 s 快照轮再评估
                set_frame(&app, 0);
                sleep(FAST_INTERVAL_SECS).await;
            }
            Some(t) => {
                // 按 6 拍循环播放一整个周期，然后重新读 CPU
                // （忙档 0.4 s/周期 × 10 s 采样窗，中途不换速）
                for beat in CYCLE { set_frame(&app, beat); sleep(t.beat_ms).await; }
            }
        }
    }
}
```

关键实现约束：

| # | 约束 | 理由 |
|---|---|---|
| 1 | macOS 换帧一律 `set_icon_with_as_template(frame, true)`，Windows 走 `set_icon` | tauri 文档明示两次调用会闪烁；组合 API 原子换帧 |
| 2 | `set_icon` 返回 `Err` 只记日志，**不 panic、不中断循环** | 图标失败不能带崩采样主循环 |
| 3 | 相同帧不重复 set（记录 `last_frame`） | 减少 30% 无谓的主线程跳转（往返节拍里 f1/f2 会出现两次） |
| 4 | 动画循环 `tokio::spawn` 于 setup，与采样循环解耦 | 采样失败/慢不影响图标，图标失败不影响采样 |
| 5 | 每 10 s 只在中途换**速度**不换档语义（周期内播完再评估） | 避免 6 拍循环中途变速的视觉撕裂 |

### 4.4 T3 · 开关、菜单与文档（~0.2 天）

| 项 | 内容 |
|---|---|
| 右键菜单 | 加「CPU 动画」开关项（默认开）。状态持久化到 `paths::config_dir()/settings.json`（W1 已有平台路径层，无新依赖） |
| 关闭行为 | 关闭后回到现有静态图标（macOS 模板 / Windows 彩色），tooltip 保留 CPU 数字 |

## 5. 与 M5 的关系

| 项 | 说明 |
|---|---|
| 数据依赖 | 只消费 `MemSnapshot.cpu.usage`（整机均值），不需要进程级 CPU——即使 M5 的 C1/C2（列表列/排序）缓做，本方案也能独立上线 |
| 提交顺序 | M5-C0 → 本方案 T1 → T2 → T3 → M5-C1/C2。动画的可见收益大、改动面小，优先于列表改造落地 |
| 口径一致 | 档位阈值基于「近 10 秒均值」口径（M5 §3.3），面板 hero 与图标档位永远同源，不会出现「面板 8% 但图标狂转」 |

## 6. 风险矩阵

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| macOS 换帧闪烁（两次渲染） | 高（若用错 API） | 中 | 强制 `set_icon_with_as_template`；T2 验收项专门目测 |
| 模板标志被换帧重置 → 深色菜单栏图标消失 | 低 | 高 | 组合 API 每帧显式传 `true`，不依赖遗留状态 |
| 档位在阈值附近来回跳 | 中 | 低 | 采样粒度 10 s 天然低频；实测跳动再加 ±5% 迟滞 |
| 动画引起电量焦虑 / 分心 | 低 | 中 | 空闲档完全静止（多数时间静止）；T3 提供开关 |
| Windows 深色任务栏看不见黑帧 | — | — | 直接给彩色帧（W3 已踩过，不再犯） |
| `set_icon` 主线程跳转过频 | 低 | 低 | 忙档上限 10 fps；相同帧跳过；实测 last_fast_ms 不受影响 |
| 帧图重心不稳，换帧时图标「晃」 | 中 | 低 | 只转刀刃角度，画布/刀柄位置逐帧一致；T1 肉眼验收 |
| 读 CPU 失败仍按旧值狂转 | 低 | 中 | `usage=None` → 立即回静止档，宁可少动不可假动 |

## 7. 验收标准

| # | 项 | 通过条件 |
|---|---|---|
| 1 | 静止档 | CPU <10% 时图标完全静止（闭合帧），无任何定时器唤醒（日志确认） |
| 2 | 档位正确 | 人为制造负载（多开 `yes > /dev/null`）：过 40% 后变中速、过 70% 变快速；负载撤掉后 ≤10 s 回静止 |
| 3 | 无闪烁 | macOS 深色/浅色菜单栏各目测一次，快速档连续播放 30 s 无闪烁、无变形、无位移 |
| 4 | 未知即静止 | 杀掉 CPU 采集（临时改代码模拟 `cpu=None`）→ 图标立即静止，tooltip 不显示 CPU 数字 |
| 5 | 开关 | 菜单关掉动画 → 回静态图标；重启 Prune 后设置保留 |
| 6 | 交互回归 | 点击图标弹面板、右键菜单、`tray.rect()` 定位（面板/主窗口）全部不受动画影响 |
| 7 | 性能 | 忙档 10 fps 持续 1 min：`last_fast_ms` 无变化；活动监视器 CPU 增量 <1% |
| 8 | 跨平台 | `cargo check --workspace --all-targets --target x86_64-pc-windows-gnu` 0 error；Windows 真机彩色帧可见（并入 W3 走查清单） |
| 9 | 资产 | `node scripts/gen-tray-frames.mjs` 重跑，`git diff` 为空 |

## 8. 不做项

| 不做 | 理由 |
|---|---|
| 图标显示数字（如 12%） | macOS 有 `set_title` 但菜单栏塞数字违反克制原则，且与「快慢」双通道冗余；数字放 tooltip |
| 颜色编码（绿/黄/红） | 模板图必须单色；彩色档位会让菜单栏变成仪表盘，与定位冲突 |
| 逐帧平滑动画（补间/更多帧） | 4 帧 × 6 拍已足够表达「快慢」，帧数翻倍徒增资产维护 |
| 动画速度连续映射（usage → fps 线性） | 10 s 采样粒度下连续调速是假精度；4 档足够 |
| 内存/swap 参与动画 | 「快慢」只编码一个维度；多维度编码需要图例，违背一眼可读 |
| 面板打开时暂停动画 | 用户此刻正在看精确数字，图标继续动反而保持一致性；实测若干扰再加 |
