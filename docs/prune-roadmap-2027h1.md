## 1. 结论先行

1. 【推断】**本两季度只做一件事：把一个功能已经做完的「浪费探测器」，变成能被找到、能被激活、能被诚实描述的产品。** 成功判据不是收入，是 CAI（累计激活装机）与首启→首清 24h 率。**在无签名条件下，CAI 唯一可行的代理是 D2（GUI 启动事件，已穿过 Gatekeeper），不是 D1**（见 §5.1）。
2. 【事实】**分发是唯一变量。** MIT 已拍板 → 功能 gate 不成立 → 付费池天花板千级 → 价格带被 DevCleaner $29 早鸟与 Vitals $49 提价双向挤压。旧路线图的「v1.0 商业化卡位」必须撤销。
3. 【事实】**独家性已从三条收缩到两条**（跨平台二进制探测、三包管理器重复存储）。这意味着 README 中「唯一／独家」类表述成为诚信欠账，是发布门禁项，不是文案优化项。
4. 【推断】**留存的真正载体可能不是清理，是灵动岛事件流。** 清理是一次性事件，结构性「清完即忘」（行业 30 天留存 2–4%）。但在四类事件的留存贡献被验证之前，**冻结第五类事件**。
5. 【事实】**当前装机体量下，「商业化翻案」在数学上不可判定。** 回访率 1–3% 时 70 份有效样本需 2,300–7,000 装机。这不是数据难看，是样本不够——所以路线图必须先起量、后判定，并带死亡线。
6. 【事实·2026-11-13 实测】**v0.9.3 的 macOS 产物是 ad-hoc 签名 + 未公证**（`spctl` rejected、无公证票据、dmg 容器未签名）。**决策：本两季度不购买 Apple Developer 年费、不做签名与公证**（见 §7 RK-9 与 `docs/prune-m0-signing-audit.md` §11）。代价不是「用户要点右键」，而是 **D1 口径的装机体量永久不可测**——所以本路线图把**北极星的装机代理从 D1 切到 D2**，并把「安装路径归真」升级为 Q1 硬需求（M0′，0.5 人日）。

## 2. v1.0 语义重定义

旧路线图把 v1.0 定义为「商业化卡位」，该定义随 D2 撤销而失效。两个候选：

| 候选 | 定义 | 是否能承载「分发是唯一变量」 |
|---|---|---|
| **A 分发就绪的免费 1.0** | 文档归真 + 可重复发布 + 官网/落地页/对比页齐备 + 首次安装体验闭环 | 直接服务 CAI |
| B 能力就绪的 1.0 | 两条独家能力做成可传播数据资产（版本×平台矩阵、重复存储合并建议） | 资产需要装机基数才能传播，而渠道尚不存在 |

**裁决：A。**理由：① B 的传播前提正是 A 要建的东西（渠道不存在时 Reach=0）；② footprint 口径已被复制，独家性在衰减，拖延越久 A 越贵；③ B 的两条资产不废除，降级为 Q2 传播素材。

**v1.0 = 分发就绪的免费 1.0**，目标发布窗 **2027-02 末**。1.0 发布前必须关闭的条件项：~~签名状态核查（M0）~~ **M0 已关闭（判 ad-hoc）+ 已决策不签名，替代项 M0′ 安装路径归真随 v0.9.4 交付**、排他性表述清理（M1）。

## 5. 指标与门禁

### 5.1 零遥测下唯一能拿到的读数

| 读数 | 口径 | 性质 |
|---|---|---|
| **D1 下载数** | GitHub API `assets[].download_count`，按 `.dmg`/`.msi`/`.exe` 分列 | **硬读数** |
| **D2 启动事件数** | `latest.json` 资产的 `download_count`（每次启动请求一次更新检查） | **硬读数**，推断自实现 |
| **D2 ÷ D1** | 同窗口相除 | **硬读数，但已永久降级为「趋势观察」**——不作判定，见下 |

> ⚠️ **口径变更（2026-11-13，因决定不签名）**
>
> 1. **D1 不再作为装机体量的判定口径。** v0.9.3 确认为 ad-hoc + 未公证（`docs/prune-m0-signing-audit.md`），下载→首启之间存在 Gatekeeper 摩擦，而**该摩擦在零遥测下无法从「不感兴趣」中分离**。既然决定不签名，这个断层就永久留在 D1 里。
> 2. **装机代理改用 D2。** D2 是 `latest.json` 的请求次数，**只有真正启动过 app 才会产生**——它天然已经穿过 Gatekeeper。这是本产品在无签名条件下的唯一干净体量读数。
> 3. **D2 的口径边界（新，勿漏）**：【事实】`crates/prune-cli/` 内无任何更新检查代码 → **CLI 用户完全不产生 D2**。因此 D2 只能读作「GUI 启动事件数」，**不得读作「全部用户」**；CLI 与 MCP 形态的采纳率在本产品永久不可测。
> 4. **D2÷D1 的合法用法只有一种**：看**同一口径下的相对变化**（例如换落地页文案前后、或某次社区首发前后），用来看「这次动作有没有让装机链变好」。禁止跨版本比绝对值，禁止当安装率使用。因为 Gatekeeper 行为随 macOS 版本变化（macOS 15 已收紧「右键打开」），绝对值会随用户升级而漂移，**不存在稳定基线**。

【事实】更新检查是启动时的一次 `latest.json` 请求，因此 D2 ≈ 累计启动事件数；每次 release 是新资产，计数按版本天然分段。**必须每日快照到本地 CSV**——API 不给时间序列，不抓即永久丢失；回溯历史 release 可当天下班前出完整曲线。

**口径保护约束（写死）**：`run_startup_check` 的调用时机属于 D2 口径定义的一部分。**修改它等于修改指标定义，必须同步更新本文件并重设 D2 基线，不接受静默变更。** 未来若加「启动时检查更新」开关，D2 会静默低估，看板表现为「启动数下滑」，极易被误读为用户流失并误触发门禁 B 的证伪分支。

### 5.2 首启→首清 24h 率（激活命门）

- 【事实】`cut_log` 只有 `(ts, label, bytes)`，同一次清理的各分组共享同一 `ts` → **清理次数 = `COUNT(DISTINCT ts)`**。settings 中无 `firstRun`/`installedAt`，全仓无 first-run 逻辑。
- 分母：`prune.db` 文件创建时间（btime，首启即建库），或新增本地 `scan_log(ts, level)`（1 人日，推荐）。
- **口径纪律**：只能叫「首启→首清」，**不得写作「安装→首清」，不得与 Release 下载数直接相除**——下载→首启之间有一个由 Gatekeeper 造成的断层，**在不签名的前提下这个断层不可分离**（故 D1 已降级，见 §5.1）。
- **征募点必须在「首扫完成 → 结果页」**。放成绩单页会让样本只含已清理者，分子分母同源，指标恒等于 100%，永久作废。

### 5.3 门禁表（含阈值性质）

| 门禁 | 判据 | 阈值性质 | 依赖的假设参数 / 被推翻后怎么动 | 判定时点 |
|---|---|---|---|---|
| C · 加投 Windows | 单次发布窗口 `.msi+.exe` 下载占比 ≥15%；判负：连续 2 版 <5% | **硬读数** | 无 | 每次发布 T+7 |
| B · 砍事件流 | 访谈自由回忆「注意到过顶部提示」自报率的 **Wilson 95% 上界 < 30%** ⇒ 判证伪（**分母只算活跃组 n=20**） | **单层可测**（无折减系数） | 无 | **T+21（活跃 20 人收满）** |
| A① 体量：**任一周 D2 ≥800** | D2 口径（GUI 启动事件，已穿过 Gatekeeper） | **软阈值** | ~~D1 ≥3,000~~ **因不签名已废止**：D1 含不可分离的 Gatekeeper 摩擦，不依赖 r₁/r₂，改用 D2 后**不再需要安装成功率假设**。注意方向：D2 是启动**事件**数 ≥ 实例数，故本条对「体量」偏宽松、对「真有人在用」偏严格 | 2027-04-30 |
| A② 首启→首清 24h 率 ≥30% | 见 §5.2 | **软阈值（样本量侧）** | 阈值是产品判断（不动）；n=70 依赖 p 先验 0.25，p 落实 0.15 则 n→100 才保 ±10pp | 2027-04-30 |
| A③ 第 8 天回访率 ≥8% | T+0 征募、T+8 二次触点 | **软阈值** | 8% = 行业 2–4%（有来源）× 2 倍（经验值、无来源）；首轮实测落 3–5% ⇒ 改为「≥6% 且显著高于同批落地页流量的自然回访」 | T+30 |

**读不出来时判什么**：软阈值的假设参数未校准时，结论一律记「**不可判定**」，不得当判负处理。这是门禁表最重要的一列——它决定 Q2 末是「判死」还是「承认测不出来」，两者对产品的处置完全不同。

### 5.4 门禁 B 为什么必须是上界而不是比例

【事实】n=8 时，**连 0/8 的 Wilson 95% 上界都是 32.4%**（1/8 为 47.1%，2/8 为 59.1%）——8 人样本无论观察到多低的比例，都无法在 95% 置信下否证 30% 这条线。更严重的是误杀率：真实触达率恰好卡在 30% 时，n=8 会以约 55% 的概率判证伪。

| 读数 | Wilson 95% 上界 | 能否判「<30%」 |
|---|---|---|
| 0/8 | 32.4% | 否 |
| 2/8 | 59.1% | 否 |
| 0/20 | 16.1% | 能 |
| 1/20 | 23.6% | 能 |
| 2/20 | 30.1% | 否 |

**定档：活跃组 n=20，最小可行判定为 1/20。** 不做 n=8 序贯早停（早停在本样本量下无统计意义）。**「n<20 不出判定，只记素材」**；交付物是「一个上界 + 一次定性归因」，不是「一个百分比结论」。

**分母只有一个合法定义：活跃组（见过首扫完成页）**。流失组与单侧用户不算分母。这不是精细度问题——分母写错会直接把结论虚报 1.7 倍：

| 真实读数 | 换算身份 | 上界 | 能否判「<30%」 |
|---|---|---|---|
| 1/15 | 分母错填（流失用户混进分母，活跃仅 15） | **29.8%** | 差 0.2pp「过关」，实际触达率被虚报 1.7 倍 |
| 1/20 | 正确分母（活跃组 20 人） | **23.6%** | 明确过关 |
| 0/20 | 正确分母 | 16.1% | 过关 |
| 2/20 | 正确分母 | 30.1% | 不能判 |

（Wilson 95% 上界；同一次命中数在错误分母下会凭空「过线」，这是本门禁唯一的四舍五入陷阱。）

**样本构成**：活跃 20 人（分母）+ 流失 3–5 人（归因素材，不进分母）= 23–25 人。成本较原估 +1 运营日。

**分组纪律**：触达自报率在活跃 20 人合并口径上算，**不得用活跃组 5 人的比例下判定**（0/5 上界 43.4%、1/5 上界 55.6%）。流失组只记「是否知道有此功能 + 为什么没用起来」，作流失归因主料。

**门禁 B 与门禁 A 不共用样本**：B 是访谈采集（T+7～T+21），A 是回访采集（T+0 征募 / T+8 触点）。两个门禁不得共用样本，否则同源误差会同时污染两侧判定。

### 5.5 时点必须错开（否则会被读成「Q1 什么结论都没有」）

| 时点 | 能得出什么 | 不能得出什么 |
|---|---|---|
| T+14（访谈中途） | 只记素材，**不出任何结论**（n<20 无判定力） | 任何比例、任何方向性判断 |
| T+21（门禁 B，活跃 20 人收满） | 事件流留存叙事「是否被证伪」的判定（Wilson 上界）；流失归因素材；Gatekeeper 拦截报告数（否决通道） | 任何激活率／留存率的数字 |
| T+30（门禁 A③） | 第 8 天回访率、首清 GB 中位数、活跃天数比 | 装机点值（D1 已废；D2 只能给趋势与事件数，不是装机数） |
| 2027-04-30（门禁 A 全部） | 三项逐条判定 + 死亡线是否触发 | 真实 DAU／留存曲线／功能使用率（永久不可测） |

**Q1 末的诚实状态**：门禁 A 在 Q1 内不可能完成（需 T+0 征募 + T+8 触点 + n≥70）。Q1 末可得的是 **D2 曲线与趋势、D2÷D1（只作趋势）、门禁 C 读数、门禁 B 方向**；**装机区间已不再可得**（D1 含不可分离的签名摩擦）。任何「Q1 末交门禁 A 结论」的承诺排不出来。

**引用纪律（写进本文与后续所有引用这份数据的文档）**：访谈产出的数字只有三种合法形态——**下界 / 区间 / 定性素材**，不得写成点估计。

| 量 | 唯一合法形态 | 禁止写法 |
|---|---|---|
| r₂ 安装拦截率 | 单向证伪：报告数／样本数作为**下界** | 「拦截率约 X%」 |
| p 先验（首扫当场清） | 20 人合并的**区间** | 「约 25% 的用户会当场清理」 |
| 触达自报率 | **Wilson 95% 上界** | 「触达率是 X%」 |

T+14～T+21 之间招募仍在并行进行（窗口 T+7～T+21），**日历不推迟**；只是「判定」动作统一在收满 20 份后执行，此前任何读数均按上表标注形态、不出判定。

### 5.6 永久不可测的量（诚实清单）

真实 DAU/MAU、功能使用率、留存曲线、卸载率、崩溃率、安装成功率、平台×留存交叉。因此以下决策**永远只能靠判断，不能靠数据**：自动清理做不做、某监控 tab 砍不砍、Windows 值不值得。任何声称「用数据决定」这些事的方案，都是在编数据。

## 6. 决策时间窗与死亡线

| 决策点 | 拍板时点 | 建议 | 逾期默认 |
|---|---|---|---|
| **DP-1** Q1 首交付 | 2026-12-15 前 | A 先建入口（R13→R09），与 M2 并行 | A |
| **DP-4** 排他表述尺度 | 2026-12 上旬 | A 全删，改可核验事实陈述 | A |
| **DP-3** 激活路径形态 | 2026-12 下旬 | B 首扫后引导卡 + 一键🟢 + 成绩单弹窗（拒绝强制 5 步线性） | B |
| **DP-5** 第五类事件 | 2027-02-20 前（M-B 备忘出来即可拍） | A 冻结至四类留存读数出结果 | A |
| **DP-2** 商业化形态 | 2027-02-15 前 | A 本两季度非商业 + Sponsors | A；门禁 A 判正方可翻案 |

**DP-3 为什么选 B**：强制 5 步线性 onboarding 会在**首扫之前**插步骤，把「需求时刻（磁盘红）」与「决策时刻（首扫惊讶）」混为一谈。首扫大数字是「惊讶不是危机」，在惊讶之前设卡会流失。

**死亡线**（写进路线图，不留解释空间）。**因决定不签名，口径已从「装机估算」改为「样本可达性」**——原版用 D1 反推装机需要 r₂ 假设，而那正是现在最不可信的一环。新口径不需要任何假设：**回访样本能不能凑够，是直接可数的。**

| 时点 | 条件 | 动作 |
|---|---|---|
| 2027-03-07（早检） | 任一周 D2 < 100 且 4 周趋势不升 | 早期警报：这不是样本问题而是需求问题 → 提前定案「单平台免费 + Sponsors」，不再等 Q2 |
| 2027-04-15 | **累计有效回访样本 < 70 份** | 门禁 A 数学上不可判定 → 作废 → 定案「单平台免费 + Sponsors」 |
| 2027-05-31 | 三项全部达标（A① 任一周 D2 ≥800 · A② 首启→首清 ≥30% · A③ D8 回访 ≥8%） | 允许重开商业化讨论；任一未达 → 永久非商业，文档固化 |

> **为什么这条更严了**：回访转化率 1–3%，70 份样本需要 2,300–7,000 量级的装机。原版「装机 <2,000」是估算出来的，新版「样本 <70」是数出来的——**后者没有辩解空间**。这是不签名带来的唯一一处「被迫诚实」，也是它最大的正面副作用。
