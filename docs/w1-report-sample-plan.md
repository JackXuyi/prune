# W1-2 体检样例报告自动化方案（report-sample）

> 版本 v1.0 ｜ 2026-11-17 ｜ 基线 **v0.13.1**（`package.json`）
> 输入：`docs/prune-sellable-position-2026-11.md` §7（90 天验证 W1–2）、`crates/prune-cli/src/doctor.rs` / `docs_json.rs`（代码级核验）
> 标注约定：**【事实】**可追到文件/代码 ｜ **【估算】**有依据未验证 ｜ **【假设】**需数据校准
> 合规声明：本方案为产品设计参考，具体实施请结合公司合规与法务要求确认。

---

## 0. 一句话

> `pnpm report:sample` 一条命令：**采集**（现有 CLI 的 `--json`）→ **组装**（模板 + 断言）→ **渲染**（MD + PDF），60 秒产出一份可直接发给买家的体检报告；报告内**每个数字都带来源命令**，**每个读不到的项都带原因**。

这两条（可溯源、不掩盖读不到）就是报告对买家的全部卖点——它们不是文案，是 `doctor` 已有的数据结构。

---

## 1. 为什么把「手工拼」改成「脚本拼」（对 W1–2 的修正，不是推翻）

原方案写"不写代码、手工拼"，意图是不花工程产能。核对代码后成本结构已变：

| 【事实】 | 出处 | 对本方案的意义 |
|---|---|---|
| `prune doctor` 已交付：四域（disk/mem/port/net）30 秒出结论，`--json` 输出 `findings` + `coverage` | `doctor.rs` | **报告的主骨架已经存在**，不需要新探测 |
| `Finding` 结构自带 `evidence[{label,value}]`、`unreadable: Option<String>`（非空=结论建立在"读不到"上，必须写原因）、`next[]` | `doctor.rs:108-129` | 报告的两个卖点字段是**现成的契约**，不是新增 |
| 契约 v1 已落地：`cli-contract.v1.json`（`schemaVersion` + 每命令顶层键 + 退出码表），快照测试守门 | `docs_json.rs:146-267` | 脚本可以**锁版本消费**，不怕字段漂移 |
| 可用命令面：`scan / mem / port / port --conflicts / app / lan / projects / doctor / watch_once` 全部带 `--json` 信封 | `docs_json.rs` | 证据明细全部现成，无需写任何探测代码 |

**手工的隐性成本**：拼一份像样的报告 1–2 天，且换一台机器要重拼一遍、数字靠手抄必错。脚本 **4 人日一次性**，之后每台机器 60 秒一份。省下的人工时间正好去做验证计划的下一件事（20 封邮件）。

## 2. 边界（四不）

| # | 边界 | 说明 |
|---|---|---|
| 1 | **不进产品代码** | 脚本住 `scripts/report-sample/`，产物住 `dist/report-sample/`（gitignore）；不动 `crates/`、不动 GUI |
| 2 | **不加探测** | 只消费现有命令的 JSON；缺数据就显示"读不到 + 原因"，绝不为此加探针 |
| 3 | **不进发布** | 这是给买家的样例生成器；D-14 产品化时把模板逻辑搬进产品，脚本退役（迁移路径见 §8） |
| 4 | **不碰红线** | 本地生成、本地交付；零遥测 / 无账号 / 不自动删，全部原样成立 |

## 3. 三步流水线（每步可独立重跑）

```
pnpm report:sample [--no-redact] [--out dist/report-sample]
   │
   ├─ Step 1 collect   采集：spawn 现有 CLI，全 --json，落 raw/*.json
   ├─ Step 2 assemble  组装：模板填充 + 五条硬断言（违者渲染失败）
   └─ Step 3 render    渲染：MD → HTML（A4 打印样式）→ PDF（Chrome headless）
```

### 3.1 Step 1 · collect（采集）

| 命令 | 报告章节 | 用途 |【事实】|
|---|---|---|---|
| `prune doctor --json` | 结论卡 + 四域 | 主骨架：`findings`（severity 排序）+ `coverage`（含 `invisible` 盲区数） | ✓ |
| `prune scan --json` | 磁盘面明细 | 白名单分组、`dup` 重复存储、`totals` 可回收合计 | ✓ |
| `prune mem --json` | 内存面 | swap 使用/总量、pressure | ✓ |
| `prune port --conflicts --json` | 端口面 | 冲突端口（"新闻"），盲区 coverage | ✓ |
| `prune projects --days 90 --json` | 项目账本 | 90 天涨跌趋势（"新闻"来源之二） | ✓ |
| ~~`prune lan`~~ | **明确不采集** | 与买家无关，且含局域网设备隐私 | — |
| ~~`net_sites`~~ | **默认不采集**（DP-R2） | 站点测速耗时 ~11s 且与买家无关 | — |

**失败处理**：单条命令失败不中止整份报告；退出码直接翻译成原因文案（3=权限不足 / 4=探测失败），写入该域的"读不到"块。**失败是内容，不是异常。**

### 3.2 Step 2 · assemble（组装）

纯 JS 拼接，**不引模板引擎**（repo 现有依赖为零模板引擎，不为一个脚本破例）。章节九段，固定顺序：

| 段 | 内容 | 卖点 |
|---|---|---|
| 1 | 元信息：生成时间、schemaVersion、Prune 版本、机器形态 | 契约可核 |
| 2 | **结论卡**：三句话 + 总可回收 GB（取 findings top3，按 severity） | 30 秒可读完 |
| 3 | 磁盘面：分级明细 + 跨平台二进制判死数 + 重复存储 + 项目账本 top 趋势 | 独家证据 |
| 4 | 内存面：swap 占比 + pressure + 换出受害者 | 口径差异化 |
| 5 | 端口面：冲突列表 + **coverage（无权限时有多少监听不可见）** | 诚实 |
| 6 | 网络面：net 域 findings | — |
| 7 | **来源附录**：数字 → 命令 → JSON 路径，一张表 | **可复核** |
| 8 | **口径说明**：phys_footprint vs RSS；0 ≠ 读不到；怀疑不下判决；🟢🟡🔴 含义 | 信任 |
| 9 | 底线声明：零遥测 / 不自动删 / 本地生成 | 底线 |

**五条硬断言（写进 assemble，违反即渲染失败）**：

| # | 断言 | 卖点来源 |
|---|---|---|
| R1 | 每个数字节点必须携带 `source`（命令名 + JSON path），渲染为脚注 | 可溯源 |
| R2 | `findings[].unreadable` 非空 → 必须渲染原因，**禁止静默** | 0 ≠ 读不到 |
| R3 | 违禁词表 0 命中：性能提升 / 优化 / 加速 / 一键 / 智能 / 最（词表独立维护，思路同 `check-docs-honesty`） | 不新增无法自证的陈述 |
| R4 | 元信息缺字段 → 显示"该字段本版本不提供"，**禁止编造** | README 纪律 |
| R5 | **脱敏默认开**：项目目录 → 项目 A/B/C；用户名路径 → `~`；主机名 → "开发机 #1"。`--no-redact` 仅本机自用 | 隐私 |

### 3.3 Step 3 · render（渲染）

- MD → HTML：内置极简 CSS（A4、打印分页、等宽数字）。
- HTML → PDF：**系统 Chrome headless**（`--headless=new --print-to-pdf`）；检测不到 Chrome 则只出 MD 并提示（DP-R3：不引 puppeteer/md-to-pdf，不为一个脚本下载 Chromium）。
- 产物：`report.md` + `report.pdf`（正文 ≤4 页 A4，来源附录与口径页不计页）。

## 10. 实现记录（2026-11-17 落地）

脚本：`scripts/report-sample/`（main / collect / assemble / render，约 900 行，**0 新依赖**）；产物：`output/report-sample/`（gitignore）。一条命令：`pnpm report:sample`。

### 10.1 验收结果

| # | 验收 | 结果 |
|---|---|---|
| A1 | 单命令 ≤60s 产出 MD+PDF | ✅ 实测 33–53s（视磁盘负载浮动） |
| A2 | 数字 100% 可溯源 | ✅ R1 断言：脚注与附录双向一致 |
| A3 | 不可读项 100% 显示原因 | ✅ 构造性验证：伪造"exit 3 + 完整 JSON"的 CLI，报告如实渲染 ⚪ + 原因 |
| A4 | 违禁词 0 命中 | ✅ R3 断言内建 |
| A5 | 产物 grep 不到用户名/项目目录/内网地址 | ✅ `grep xuyi report.md` = 0；R5 断言含用户名/主机名/项目名/私网 IP 四类 |
| A6 | PDF 正文 ≤4 页 | ✅ 实测 4 页 |
| A7 | 换机结构一致 | ⏳ 章节为固定九段模板，待第二台机器实测 |

### 10.2 与方案的偏差（均为实现中发现的事实驱动）

1. **采集分两波**：scan/mem/port/projects 并行 → doctor 独占。原方案未预见到并行会让 doctor 的磁盘域（20s 超时）与 scan 互相挤压——实测触发过一次 timeout，丢掉 disk 域读数。两波合计约 45–50s，仍在 A1 预算内。
2. **退出码 ≠ 0 仍消费 JSON**：doctor 在"全部域不可读"时打印完整 JSON 后才返回 3/4，此时 stdout 恰好带着 `unreadable` 原因。判定顺序改为"先解析契约 JSON，再看退出码"，非 0 退出码记为 degraded 并写进元信息。这是 A3 成立的前提。
3. **降级 JSON 防崩**：残缺 JSON（缺 totals 等关键字段）按"读不到 + 原因"降级，不让章节函数崩溃。
4. **结论卡只列非 🟢 结论**：🟢 不占位（否则挤掉真正需要看的结论）；`disk.reclaimable_high` 与首句"可回收合计"去重。
5. **swap 占比单一来源**：占比统一取 doctor 判定（结论卡与 §4 同源），绝对量取 mem——两个来源在实测中出现过 94% vs 93% 的采样差，与其对齐舍入不如各带脚注并在 §8 说明。
6. **产物目录 dist/ → output/**：vite build 的 `emptyOutDir` 会清空 dist/（实测发生，报告连同 raw 一起被删）。
7. **R1 断言语义**：从"来源 ≥3 条"改为"有数据必须有溯源 + 脚注与附录双向一致"——全机读不到时账本为空是合法的，正是 0 ≠ 读不到该有的样子。

### 10.3 遗留

- Chrome headless 失败时自动回退 MD/HTML（已实现，未在无 Chrome 机器上实测）。
- `--no-redact` 版与脱敏版差异实际只有项目名与网关 IP（本机报告本就不渲染含用户名的路径）；外发仍以脱敏版为准。
- raw/ 原始 JSON 未脱敏，只限本机；已在命令输出与 raw/README.txt 双重提示。
