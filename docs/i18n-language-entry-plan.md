# 语言切换方案（v4：设置页下拉菜单 + 面板入口 + 繁体落英文）

> 状态：**已实施**（2026-11-11 落地；详细 spec 见 `docs/i18n-language-switch-spec.md`）
> 日期：2026-11-11（v1 托盘方案 → v2 设置页方案 → v3 确认 P2 → v4 确认繁体策略）
> 关联：`docs/i18n-spec.md`（§1.1 标签规则、§1.5 降级链、§4.3 入口、§11 S3 / S5）

## 0. 已确认的决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | 主入口位置 | **设置页语言段**，形态为下拉菜单（不是胶囊、不是托盘） |
| 2 | 面板入口 | **做**（P2）：面板 header 加齿轮 → 打开主窗口设置 |
| 3 | 系统语言显示 | **可读名**（简体中文 / English），原始 tag 只进 `title` |
| 4 | ⌘, 打开设置 | **做**（P1） |
| 5 | 「跟随系统」的 D1 缺陷 | **去掉 `OnceLock` 缓存**，每次 `resolve` 现读 |
| 6 | 繁体系统（`zh-Hant` / `-TW` / `-HK` / `-MO`） | **落到英文**，不再显示简体文案 |
| 7 | 系统语言名映射范围 | 只映射 zh / en，其余原样显示 tag（如 `ja-JP`） |
| 8 | 「当前生效」措辞 | `当前生效：中文`（强调与偏好的区别） |

### 决策 6 的性质：这是一次行为变更，不只是 UI 调整

现在 `Locale::from_tag` 把 `zh-Hant-*` 也判成 `Zh`（`crates/prune-core/src/locale.rs:25-31`），所以繁体系统看到的是简体文案。决策 6 推翻 `docs/i18n-spec.md` §11 的 **S3**（原文：繁体用户显示简体「可接受，已知取舍」），改为落 `En`。

影响面不止设置页：

| 受影响 | 说明 |
|---|---|
| 托盘菜单 / 灵动岛 / 报告 | 繁体系统上一律英文，与设置页一致 |
| 手动选「中文」 | **不受影响**：走 `pref_from_str`，与系统 tag 无关 |
| `docs/i18n-spec.md` | §1.1 代码片段、§971 测试清单、§11 S3 三处要同步改 |
| `docs/i18n-plan.md:361` | 同一规则的历史表述，需加注或改 |

理由：catalog 只有简体，繁体用户看到的是「用词与标点都不对」的简体，比英文更难读；而英文至少是完整、正确的翻译。

选设置页作主入口，`docs/i18n-spec.md` §11 的 S5（「不加面板语言入口，只在设置里」）**不需要修订**——本方案没有给面板加语言切换，只加了「到设置」的跳板。

## 1. 为什么不是「加个入口」而是「修三条」

设置页里**已经有**语言切换（`SettingsBoard.tsx:56` `["auto","zh","en"]`，`:146-179` 三颗胶囊）。核对源码后发现三处硬伤，任何一处都足以让人以为它不存在：

| # | 问题 | 源码位置 | 现象 |
|---|---|---|---|
| **D1** | 系统语言被 `OnceLock` 锁死到进程结束 | `i18n.rs:143-162` | 在 macOS 里把语言改成英文，回 Prune 点「跟随系统」——界面不动，必须退出重开。而 `locale_set` 注释（`:201`）写着「重复点一次应当刷新」，注释与实现打架 |
| **D2** | 选「跟随系统」时看不到系统被识别成了什么 | `i18n.rs:74-79` 载荷只有 `{current, source}` | 只显示「当前：中文（跟随系统语言）」。系统是日语时回落英文，用户完全不知道为什么 |
| **D3** | 设置只有主窗口齿轮一个入口 | `MainWindow.tsx:95`；`MenuBarPanel.tsx` 无入口 | 只开面板的用户到不了设置 |

## 2. 方案形态

设置页的语言卡片，从三颗 11 px 胶囊换成一行下拉：

```
语言                        跟随系统（简体中文） ⌄
当前生效：简体中文
```

展开（宽 260 px，右对齐）：

```
┌──────────────────────────────┐
│ ✓ 跟随系统                    │
│   系统语言：简体中文           │
│   中文                        │
│   English                     │
└──────────────────────────────┘
```

- 勾选落在**当前偏好**（`source === "manual" ? locale : "auto"`），不是当前生效语言
- 副标题只出现在 `auto` 项下，用来解决 D2
- 系统语言读不到时写「系统语言无法读取 · 暂用 English」，不静默回落
- 语言项名恒为原文（`中文` / `English`），系统语言名跟 UI 语言走（详见 spec §5.3）

**为什么换掉胶囊**：它是设置页里最小的控件（11 px），语言却要一眼找到；现在三种语言就撑满一行，加日语必炸；下拉能塞副标题，正好装 D2 要的信息。

## 3. 入口拓扑

| 入口 | 覆盖场景 | 阶段 | 实现要点 |
|---|---|---|---|
| 设置页语言下拉 | 主窗口内 | P1 | 本节主体 |
| ⌘, | 主窗口内，省掉找齿轮 | P1 | `MainWindow.tsx:295` 键盘分支加一条 |
| 面板 header 齿轮 | 只开面板的用户（D3） | P2 | `open_main` 加 `settings` 目标 → emit `ui://settings` → 主窗口 `setSettingsOpen(true)` |

**面板入口为什么放 header 不放页脚**：header 右侧已有刷新 / 展开主窗口两个 `IconButton`（`MenuBarPanel.tsx:72-80`），齿轮与它们同组属「动作区」；页脚是读数信息区（`panel.footer.*`），塞按钮会让「最后深探时间」被迫换行。用同尺寸 `size-6` 按钮，行高不变，`PANEL_H = 432` 不用动。

**不做**：托盘子菜单（需要一份平行的 `TrayText` 表，同一件事两份 source of truth）、顶栏常驻语言按钮（误触会把整个界面换语言）、首次启动语言弹窗（Rust 侧探测可靠，弹窗只是替用户决定）。

## 附录：v1 托盘方案的取舍留痕

v1 主张「托盘语言子菜单 + ⌘,」，理由是任何窗口状态下都能到达。降级的实际原因：

- 托盘菜单已有 6 项 + 主题子菜单（`tray.rs:224` 起），再加子菜单会把「日常操作」与「偏好设置」混在一层
- 需要一份平行的托盘文案表（`TrayText` 加 4 字段），与前端 catalog 构成第二份 source of truth，最容易漂移
- 「所有窗口都关闭时切语言」是极低频场景；真要做，加一个「设置…」单项打开主窗口设置即可，不必复制子菜单设计
