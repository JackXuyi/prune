# M4 · 内存域 / 存储域分离方案

> 状态：已实施（2026-10-29，按推荐 B 路径 S0→S2 全部落地）· 前置：M0 tray / M1 磁盘 / M2 内存 / M3 NSPopover 均已完成
> 原则：内存（RAM）与磁盘存储（SSD 卷）是两个独立资源域，展示上分区、心智上分开；关联点（swap）保留但只挂一处。

## 1. 结论（TL;DR）

1. **现状 3 处混排**（§2）：面板首屏只有磁盘主数字、概况 tab 内存与磁盘上下无缝混排、swap 的磁盘占用措辞歧义；存储域整体缺「卷容量」上下文。
2. **方案**：信息架构拆成**内存域 / 存储域**两条主线——面板 hero 改双行分区（内存一行 + 存储一行），概况 tab 拆成两个 tab，主窗口 tab 语义对齐；数据层给 `DiskReport` 补卷容量（statfs）。
3. **分三个阶段**（S0 数据层 → S1 面板 → S2 主窗口），每阶段独立可验收，工作量约 1.5~2 天。

## 2. 背景 · 现状诊断

| # | 位置 | 现状 | 问题 |
|---|------|------|------|
| 1 | 面板首屏 `DiskHero` | 只展示「可回收 GB」磁盘主数字 | 内存状态缺位；用户打开面板第一眼看到的是存储，不是内存 |
| 2 | 面板概况 tab | `MemSection`（内存压力/swap/换出受害者）与 `DiskSection`（可回收分层）上下紧排，仅一条分隔线 | 内存和磁盘无视觉边界、无独立入口，扫一眼分不清哪个数字属于哪个域 |
| 3 | 面板 swap 卡片 | 「↳ 正在吃掉磁盘 7 GB」 | swap 是内存压力的出口，措辞让它看起来像磁盘功能，归属歧义 |
| 4 | 主窗口 | 三 tab：应用内存 / 系统概况 / 可回收 | 「可回收」的 GB 是孤立数字——没有卷总容量/剩余空间做分母，用户无法判断清理 45 GB 意味着什么 |
| 5 | 数据层 | `DiskReport` 无卷容量字段（grep 证实无 statfs） | 存储域缺地基，任何容量分母都展示不出来 |
| 6 | swapfile | 占用的磁盘容量无任何视图 | 存储域里它是真实的容量项（可能数十 GB），当前完全不可见 |

## 3. 需求理解

- **分开展示**：内存容量（物理内存占用、压力、换出）与磁盘存储容量（卷容量、剩余、可回收）分区呈现，各自有明确的标题、图标、入口与读数体系。
- **不是删除关联**：swap 是两个域的接口——在内存域作为「压力出口指标」，在存储域作为「容量占用项」，各挂各的语义，不重复渲染主数字。
- **两端的用户动作不同**：内存域的动作是「减压」（结束进程、排查泄漏），存储域的动作是「腾空间」（清理可回收项）——分区后各自的 CTA 也应各归各位。

## 4. 信息架构：两个选项

| 维度 | A · 两域两 tab（推荐） | B · 保持三 tab 改名 |
|------|----------------------|-------------------|
| 主窗口 | 「内存」（应用+系统概况合并） / 「存储」（卷容量+可回收） | 「内存 · 应用」「内存 · 概况」「存储」 |
| 心智清晰度 | ★★★ 两域彻底分开 | ★★ 存储独立了，内存仍占两 tab |
| 改动量 | 大：概况与应用合并、布局重排 | 小：只改 tab 文案 + 存储侧加容量条 |
| 风险 | 应用内存列表 + 概况同屏，960px 布局要重设计 | 几乎无风险 |
| 回滚成本 | 高 | 低 |

**推荐：分阶段走 B → A 的中间态。** 即 S1/S2 先按 B 落地（低风险拿到「分开」的核心收益：面板分区 + 存储域完整化 + 措辞纠偏），若验证后仍觉主窗口内存两 tab 拥挤，再演进到 A。理由：当前主窗口三 tab 各自内容密度已接近一屏，合并反而增加单屏负载；「分开」的痛点主要在面板与措辞，B 已解决。

### 目标信息架构（按 B）

**面板（380×560）**

```
┌──────────────────────────────┐
│ Prune          [刷新] [打开]  │
├─ 内存域 ─────────────────────┤
│ ● 压力正常   已用 12.1 / 16 GB │ ← hero 上行：内存
├─ 存储域 ─────────────────────┤
│ ⚡ 45.2 GB 可回收   剩余 98 GB │ ← hero 下行：存储
├──────────────────────────────┤
│ [应用] [概况]      (内存域 tab)│
│ …                             │
└──────────────────────────────┘
```

- hero 双行，各带域标题（内存 / 存储），左对齐图标区分（内存用 PressureDot，存储用 ⚡/DiskIcon）
- 概况 tab 中的 `DiskSection` **移除**（存储信息已上移到 hero，入口是 hero 点击 → 主窗口存储 tab）
- swap 卡片措辞改为「swapfile 占用 7.0 GB（见存储域）」，去掉「吃磁盘」歧义

**主窗口（960×640）**

```
tabs: 内存 · 应用 | 内存 · 概况 | 存储
```

- 「存储」tab = 现「可回收」+ 顶部**卷容量条**（已用 X GB / 总 Y GB · 剩余 Z GB，含可回收占比高亮）
- 「系统概况」→「内存 · 概况」，纯内存语义；swap 区块保留但标注存储占用
- 可回收数字从此有分母：「可回收 45.2 GB · 相当于剩余空间的 46%」

## 5. 模块设计（S0 → S1 → S2）

### S0 数据层：卷容量（地基，~0.5 天）

| 项 | 内容 |
|---|------|
| Rust | `prune-core/src/disk` 新增 `VolumeInfo { total_bytes, available_bytes, user_available_bytes }`，用 `libc::statvfs` 取 home 所在卷（APFS 的 purgeable 空间会让 `available` > `user_available`，展示用后者，两个字段都留） |
| 报告 | `DiskReport.volume: Option<VolumeInfo>`——Option 保证旧报告/序列化兼容；扫描入口处每次取实时值（不参与扫描耗时） |
| 前端 | `types/disk.ts` 镜像 `volume?` 字段；`ipc.ts` 无需改（随 report 透传） |
| 验收 | cargo test 补 statvfs 单测（total > 0、available ≤ total）；旧报告 JSON 反序列化不炸 |

### S1 面板分区（~0.5 天）

| 项 | 内容 |
|---|------|
| `DiskHero` → `DomainHero` | 双行结构，内存行读 `useMemStore`（physicalTotal、pressure.level），存储行读 `useDiskStore`（reclaimable + volume 剩余）；两行各自点击进主窗口对应 tab |
| `DiskSection` 移除 | 概况 tab 只剩内存语义 |
| swap 措辞 | 「↳ 正在吃掉磁盘 7 GB」→「swapfile 占用 7.0 GB · 存储域可查」 |
| 验收 | 面板总高不变（hero 双行压到 ≤76px）；内存行在 snapshot 为 null 时显示骨架而非空行 |

### S2 主窗口对齐（~0.5~1 天）

| 项 | 内容 |
|---|------|
| tab 文案 | 「应用内存 / 系统概况 / 可回收」→「内存 · 应用 / 内存 · 概况 / 存储」 |
| 存储 tab | 顶部加卷容量条（Meter：已用/剩余 + 可回收占比徽标）；`ui://tab` 事件值沿用 `disk` 不改协议 |
| 概况页 | 标题改「内存概况」；swap Stat 补充「占用存储 X GB」说明行 |
| 验收 | tsc / cargo check / 单测全绿；面板与主窗口读数口径一致（同一 volume 字段） |

## 7. 风险矩阵

| 风险 | 概率 | 影响 | 缓解 |
|------|-----|------|------|
| APFS purgeable 导致「剩余」虚低 | 高 | 低 | 用 `user_available`（statvfs f_bavail），单测断言两个字段关系 |
| 旧序列化报告缺 volume 字段 | 中 | 低 | `Option<VolumeInfo>` + `#[serde(default)]`，前端 `volume?` 全部空值兜底 |
| 面板 hero 双行挤压 560px 高度 | 中 | 中 | 预算 ≤76px；概况 tab 内容因移除 DiskSection 反而净减 ~120px |
| tab 改名影响文档/验收清单措辞 | 高 | 低 | S2 一起更新 docs 验收清单；`ui://tab` 协议值不改 |
| statvfs 权限/失败 | 低 | 低 | 取不到时 volume=None，UI 隐藏容量条只显示可回收（现状兜底） |

## 8. 不做项

- 外置卷 / 多卷支持（结构已预留）
- 存储域做「清理后剩余空间即时预测」（依赖系统 purgeable 行为，误差不可控）
- 内存域新增任何新指标（本方案只做分离与归属纠偏，不扩口径）
