# F20 内存报告导出（Memory Report Export）

> 状态：方案（未实施）。P1，建议搭 v0.11.0「M6 数据资产」的车。
> 竞品依据：Vitals 1.11（2026-11）新增 Memory Report——分时峰值 + 每进程 + CSV，
> 供用户附在 bug 报告 / 性能工单里。需求已被验证，Prune 的数据层（M2 序列库）现成。

## 一、背景

- Prune 已有 7 天 × 5 min 粒度的每进程内存序列：`db.mem_process(ts, pid, start_time, name, family, rss, footprint, swapped)`（`crates/prune-core/src/db.rs`，`Store::record` 每轮落库，`Store::series` 读回，`sampler.rs RETENTION_SECS = 7d`）。
- 用户诉求是「把这段时间的内存表现拿给别人看」：附工单、贴 issue、对比加内存前后。目前唯一出口是 GUI 曲线截图——没有数值、不能排序、不能二次加工。
- 边界纪律：导出是**读历史**，不是诊断。方案只做格式化搬运，不做任何「结论生成」（泄漏嫌疑归 mem_leaks， swap 判断归 M3）。

## 二、成功标准

1. 用户在内存 tab 一键导出 CSV，用 Numbers / Excel 打开列语义清晰、无合并单元格。
2. CLI `prune mem --csv <path>` 产出同一格式（同一聚合函数，非两条代码路径）。
3. 导出范围默认 7 天（序列库全窗口），可选 `--since <h>` 缩短；不扩大保留窗口。
4. 大文件可控：7 天 ≈ 2k 行/进程 × 50 进程 = 峰值 10 万行内，CSV < 10 MB。

## 三、不做什么

- **不做 HTML/PDF 报告**——Vitals 的报告页好看但不可二次加工；CSV 是数据资产的正解。
- **不做结论字段**（「是否泄漏」「是否该加内存」）——口径争议大，导出物必须纯观测。
- **不改保留窗口**——7 天就是序列库的真相边界，超出部分诚实标 `coverage`。
- **不做 MCP 工具**（本期）——`mem_leaks` 已覆盖 agent 场景的嫌疑侧，导出是人的场景。

## 四、方案

### 4.1 核心聚合（prune-core/src/mem/report.rs）

纯函数：输入 `&[MemRow]`（从 `Store::series` / 新增 `Store::report_rows(since)` 读全量行），
输出 `MemReport`：

```rust
pub struct MemReport {
    pub from_ts: i64,
    pub to_ts: i64,
    /// 每进程一组：按峰值 RSS 降序
    pub procs: Vec<ProcMemReport>,
    /// 采样空窗说明（Prune 没跑的时段），随 CSV 尾注输出
    pub gaps: Vec<(i64, i64)>,
}
pub struct ProcMemReport {
    pub name: String,
    pub family: String,
    pub pid: i32,               // 末次观测 pid（进程会重生，pid 只是锚点）
    pub peak_rss: u64,
    pub peak_swapped: Option<u64>,
    pub avg_rss: u64,
    pub samples: u32,           // 0 样本的进程不进表
}
```

设计决策：
- **聚合维度 = (name, family)**，不按 pid 分行：同一进程重生（pid 变）在报告里是一行——
  用户关心的是「Safari 这 7 天」，不是「pid 626 那段」。pid 只作为末次锚点附带。
- **峰值取原始样本最大值**，不做小时降采样后再取峰（会丢尖峰——报告的价值恰在尖峰）。
- **空窗（gaps）必须进报告**：Prune 没跑的时段不能让读者误以为「当时很干净」。
  判据：相邻样本间隔 > 3 × 采样周期（10 min）记一段。

### 4.2 CSV 格式

```
section,ts,name,family,pid,rss_mb,swapped_mb,samples,note
summary,<from>,,,,,,,7d window
summary,<to>,,,,,,,
gap,<start_ts>,,, ,, ,,"Prune 未运行 3h12m"
proc,<peak_ts>,Safari,app,1234,2841.3,0.0,1876,
proc,<peak_ts>,node,project:prune,5678,412.9,,231,末次 pid
```

- 单位进列名（`rss_mb`），不在单元格写「MB」——机器可读优先。
- 尾注写生成时刻与 Prune 版本（`# generated by Prune vX.Y.Z at ...`）。

### 4.3 CLI（prune-cli）

`prune mem [--csv <path>]`：已有 `mem` 子命令加 flag，**不开新子命令**（cli-reference
11 子命令契约不动，只扩 flag，`check:docs` 同变更）。无 store 时（无 db 文件）输出
「暂无序列数据」并指路 GUI，退出码 0——不是错误。

### 4.4 GUI（src-tauri + 前端）

- `mem_export_csv(since_hours)` 命令：聚合 → 临时文件 → `tauri-plugin-dialog`（已在
  Cargo.toml，Rust 侧 DialogExt 调用，无需 JS ACL——与「检查更新」弹窗同款）save 对话框
  → 写入 → 返回路径。**取消保存 = 无事发生**，不弹错误。
- 内存 tab（StatsBoard 头部）加「导出 CSV」按钮：hover 说明「导出最近 7 天每进程内存序列」；
  导出完成后 toast 路径。无序列数据（< 1 个采样周期）时按钮禁用 + 原因 tooltip。

## 六、风险与对策

- **大 CSV 卡 UI**：聚合后行数 = 进程数（不是样本数），写文件在 spawn_blocking，UI 不等写盘。
- **进程名含逗号/引号**：CSV 转义走 `csv` crate（或手写 quote 规则 + 单测），不裸拼。
- **「导出的峰值和曲线图对不上」**：曲线图若做了降采样，峰值列必须标「原始样本峰值」；
  若曲线图已是原始值则天然一致（实现时以 M2 前端读数为准核对）。

## 八、实现记录（2026-11-18）

- 落点：`mem/report.rs`（aggregate/to_csv/csv_escape 纯函数，5 单测）/ db `mem_report_rows`（全量行含 rss/swapped，与 series() 的 footprint-only 分工明确）/ CLI `prune mem --csv <PATH>`（flag 不开新子命令，11 子命令契约不动）/ `mem_export_csv` 命令（原生 save 对话框走 Rust DialogExt，取消 = None 无事发生）/ 前端 `MemExportButton` 挂内存页家族列表头部 + memory.exportCsv 双语文案。
- 与方案偏差：聚合中间槽用伴生 struct（avg_sum 不进序列化形状）；空窗周期取**中位数 ×3** 自适应采样节奏（方案写死 3×10 min，实现更稳）。
- 真机验证：`prune mem --csv /tmp/prune-mem-report.csv` → 44 进程 / 60 段空窗 / 7 天窗口，CSV 列语义清晰（rss_mb 单位进列名、gap 行带中文说明）。
- 门禁：core 537 / cli 59 全绿；tsc / check:i18n / check:docs / clippy 0 新警告。
