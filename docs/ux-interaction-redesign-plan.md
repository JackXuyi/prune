## 三、设计原则（沿用并显式化，全部为硬约束）

| # | 原则 | 落地含义 |
|---|------|----------|
| 1 | **只读呈现，破坏性操作集中** | 总览/应用/网络/端口页只呈现事实与导航；清理入口只在「存储」，结束进程入口只在「内存」与「端口」的实体行上 |
| 2 | **GB 可行动，百分比可描述** | 首屏主视觉 = 可回收 GB；百分比只作副读数 |
| 3 | **口径透明** | 每个数字带一句口径 caption（footprint/statvfs/nettop/物理网卡），hover 展开 |
| 4 | **假事实红线** | 读不到显示「不可读 + 原因」，绝不显示 0；未扫描显示「尚未扫描」，绝不显示空集为 0 |
| 5 | **破坏性操作两步确认** | 结束进程：选项→确认；清理：dry-run 清单→确认；>20GB：强制二次确认；Docker：只给命令永不执行 |
| 6 | **可见性门控** | 端口 30s 轮询、nettop 1s 采样只在该 tab 可见时运行，其他 tab 常驻开销为 0 |
| 7 | **下钻有来有回** | 所有跨 tab 跳转必须可一键返回来源（详情页顶部「← 返回」或面包屑） |

### 5.1 标题栏

| 口径 Badge（内存相关 tab） | hover 显示口径说明 | `footprint 口径`（title: `footprint 口径：含被换出到磁盘的部分`）/ `RSS 口径 · 不含换出量`（title: `footprint 不可用，全部读数退回 RSS，不含换出量`） |
| 深探时间戳 | hover 显示绝对时间 | `上次深探 3 分钟前` |
| 刷新按钮 | 单击触发该 tab 对应刷新；busy 时禁用 + 图标旋转；⌘R 全局可用 | 见 5.2 分 tab 文案 |
| 设置齿轮 | 单击打开设置弹层（Escape/点外部关闭） | title: `设置` |

### 5.2 刷新按钮文案规范（统一）

| Tab | 空闲文案 | busy 文案 | 动作语义 |
|-----|----------|-----------|----------|
| 总览 | `刷新` | `刷新中…` | 内存 + 端口重扫 + 网速快照 + 卷容量 |
| 应用 | `刷新` | `刷新中…` | 内存 + 端口 + 磁盘本体重测；网速自动跳不手动刷 |
| 内存 | `刷新` | `采样中…` | 内存快照重采 |
| 存储 | `重新扫描` | `扫描中…` | 磁盘扫描（增量/全量由页内决定） |
| 网络 | `刷新` | `刷新中…` | 快照 + 走势 + 7 日柱；不打断采样 |
| 端口 | `扫描端口` | `扫描中…` | 显式重扫一轮 |

### 5.3 三态文案规范（全局统一，收敛为文案常量库 `lib/uiText.ts`）

| 状态 | 规则 | 标准文案 |
|------|------|----------|
| 未扫描/未采样 | 显示「尚未 X」，绝不显示 0 或空表 | `尚未扫描` / `尚未采样` / `尚未测量` |
| 读不到 | 显示「不可读 + 原因」 | `不可读：{原因}` |
| 加载中 | 动词 + `…` | `采样中…` / `扫描中…` / `测量中…` / `诊断中…` / `测速中…` |
| 空结果（扫描过但为空） | 明确「没有」，与「未扫描」区分 | `没有发现可回收项` / `当前没有明显被换出的进程` / `最近一次扫描里没有该进程的监听端口` |
| 失败 | 原因 + 影响 + 出路 | `深探不可用，当前为 RSS 口径。macOS 请确认 /usr/bin/footprint 可执行；Windows 通常是该进程受保护或权限不足` |

### 5.4 结束进程菜单（全局唯一组件，3 处入口共用）

| 阶段 | 交互 | 文案 |
|------|------|------|
| 第一步（菜单） | 右键弹出；点外部/Escape 关闭 | 项 1：`结束进程` + hint `SIGTERM · 可优雅退出`；项 2（danger）：`强制结束` + hint `SIGKILL · 立即终止` |
| 第二步（确认） | 确认按钮执行；`取消` 返回第一步；出错后 `关闭` 收起 | 主句：`{结束|强制结束}「{进程名}」pid {pid} · {内存或端口}？`；副句：`发送 SIGTERM，应用可保存数据后退出` / `立即杀死，未保存的数据会丢失`；按钮：`确认`（danger）/ `取消`；busy：`执行中…`；错误：`{错误原因}` |
| 成功后 | 清空选中 + 重采内存 + 重扫端口（端口 tab 来源时） | — |

**规则**：系统进程 / 内核持有的端口不提供结束入口，行内提示 `该端口由系统进程或内核持有，不提供结束入口`。

### 5.5 快捷键（新增，增强项）

| 快捷键 | 动作 |
|--------|------|
| ⌘1–⌘6 | 切换 6 个一级 tab |
| ⌘R | 当前 tab 刷新（同 5.2） |
| ⌘F | 聚焦当前页搜索框（应用 / 端口页） |
| Escape | 关闭弹层 / 菜单 / 取消选中返回概况 |

### 6.3 主窗口 · 内存（合并「内存·应用」+「内存·概况」）

**页面目标**：一页看全「系统内存状况 + 谁占得多 + 谁疑似泄漏 + 单进程真相」。
**布局**：左栏 350px（泄漏卡置顶 + 家族列表）｜右栏（默认=内存概况；点选进程后=进程详情，顶部「← 返回概况」）。结构从 3 种形态收敛为统一的「列表 + 详情」。

| 区块 | 交互 | 文案 |
|------|------|------|
| 左栏头 | 只读 | `进程家族 · {n} 个 · 按总量降序` |
| 家族行 | 单击展开子进程；子行单击选中进详情；右键弹结束菜单 | 主行：`{家族名}` + `{n} 个进程{ · m 个项目}{ · RSS|· ≈}` + `{≈}{总量}` + `{x% 在磁盘|—}`；title（子行）：`点击查看明细 · 右键结束进程` |
| 泄漏卡（有命中才出现） | 点击嫌疑项 → 同页选中该 pid 进详情 | 见 6.3.1 |
| 右栏默认（概况） | 只读 | 见 6.3.2 |
| 右栏详情（选中进程） | 「← 返回概况」回默认态 | 见 6.3.3 |

**6.3.1 泄漏卡（克制措辞，概率 + 证据）**

## 七、数字呈现与图表规范

### 7.1 问题：数字全是文字，比例全靠心算

| 现状 | 用户实际要做的脑内运算 | 后果 |
|------|------------------------|------|
| `24.1 / 36 GB` | 24.1 ÷ 36 = 67%，然后判断「算不算高」 | 每看一次算一次 |
| `swap 已用 93%`（配色区分） | 93% 距危险还有多远？没有刻度参照 | 只能靠颜色记阈值 |
| `L1 7.74 / L2 22.5 / L3 21.7 / L4 3.0 GB` | 四项相加 ÷ 主数字，才知道谁是大头 | 分级失去「分级」意义 |
| 应用卡六行字段 | 8.4 GB 和 6.1 GB 差多少？无相对参照 | 排序能解决名次，解决不了量级差 |
| 诊断三层 `23.4 / 8.1 / 128 ms` | 三个数各自和阈值比 | 主因结论要靠文字读 |
| 端口 `23 个` | 关注层/对外/其他各多少？ | 只能进页内数行 |

**结论**：本项目的数字已经做到「口径透明」，但缺一层「量级可见」。补图表的目的是**省掉心算**，不是美化。

### 7.2 图表选型矩阵（按数据形态，不按页面）

| 数据形态 | 呈现构件 | 判断依据 | 典型落点 |
|----------|----------|----------|----------|
| 单值占总量比（0–100%） | **MeterBar**（水平条） | 单一比例，需与阈值对照 | 内存占用、硬盘占用、swap、CPU 卡 |
| 总量由 2–4 段构成 | **StackBar**（堆叠条） | 段间是"构成"关系，且合计有意义 | 可回收 L1–L4、footprint = RSS + 换出、磁盘三层 |
| 多个实体的同一指标比大小 | **BarList**（排序条列表） | 实体数 ≥ 4，文字表已能排但看不出量级差 | 网卡分布、按应用流量、端口分组 |
| 同量纲 2–3 项对照 | **CompareBar**（现有） | 项目已有组件，保留 | 内存构成明细行 |
| 短窗口时间序列（≤ 4 h） | **Sparkline**（现有） | 只看"在涨还是在抖" | footprint 走势、CPU 10 min、下载/上传 5 min |
| 7 天日聚合 | **柱状图**（现有） | 日粒度离散比较 | 网络 7 天流量 |

| 状态（正常/警告/危险） | 状态点 / 徽标 | 离散状态，不画图 | 内存压力、口径 Badge |
| 明细清单（进程、端口、文件路径） | 表格 / 列表 | 精确值优先 | 家族列表、端口表、可回收明细 |

### 7.3 明确不做（范围红线）

| 不做 | 理由 |
|------|------|
| 饼图 / 环形图 | 超过 3 类不可读，且本项目构成项常 ≥ 4；占比一律用条 |
| 双 Y 轴、3D、渐变面积图 | 误导性强，与「口径透明」原则冲突 |
| 任意指标的历史时间序列 | README 已明确排除（只有 CPU 10 min、网络 5 min、7 天日聚合）；本期**不新增任何采样或落库** |
| 图表内交互（缩放、刷选、tooltip 浮层） | 960×640 窗口内成本高收益低；精确值由旁边的数字文本承担 |
| 入场动画 / 数值滚动动画 | 与轻量、常驻低开销定位冲突；只在 hover 给 120 ms 颜色过渡 |

**数据来源约束（硬）**：所有图表数据必须由**现有快照或现有序列**前端派生，不得新增 IPC 采样频率、不得新增 SQLite 表。图表层只是 `statsReadout.ts` 之上的纯展示。

| 轨道 | `ink/[0.08]`，不加边框 |
| 填充色 | 单条只有一个语义色：正常 `accent`、告警 `warn`、危险 `danger`、中性 `neutral`；同图 ≤ 2 个色阶 |
| 堆叠段 | 段间不留缝，用 1 px 背景色描边分隔；某段 < 2 px 宽时**不画色块但保留数字**（不允许为可见性虚增比例） |
| 阈值刻度 | 1 px 虚线 + 端点短标签（如 swap 的 `75` / `90`） |
| 基准对齐 | 同一页内所有 MeterBar 轨道等宽（卡片内容区宽），条与数字左对齐，数字在条上方 |
| 数值位置 | **数字永远在图上方的文本位**，不压在条内（避免对比度不足） |
| 空值 | 不画轨道填充、不留 0 长度条；显示 `—` 或「不可读：{原因}」——延续「0 与读不到是两件事」 |
| 无障碍 | 每个图形 `role="img"` + `aria-label="{指标} {值}，占 {x}%"`；颜色不作为唯一信息载体（配数字/标签） |

### 7.5 数字格式统一（收敛为 `lib/format.ts` 单一来源）

| 类型 | 格式 | 示例 |
|------|------|------|
| 容量 | GB 一位小数，< 1 GB 自动切 MB 整数 | `3.4 GB` / `812 MB` |
| 百分比 | 整数，不补零 | `93%` |
| 速率 | 一位小数 + 自适应单位 | `3.2 MB/s` |
| 计数 | 千分位 | `1,204` |
| 相对时间 | < 1 h 用分钟，< 1 min 用「刚刚」 | `3 分钟前` |
| 估算值 | 前缀 `≈`（仅 RSS 混合口径时） | `≈3.4 GB` |

## 八、文案规范与术语表

### 7.1 术语统一

| 术语 | 用法 | 禁用 |
|------|------|------|
| 口径 | footprint / RSS / statvfs / nettop 等数据来源说明 | 「统计方式」「算法」 |
| 换出 | 进程内存被移到磁盘 | 「交换」「swap 掉」（正文） |
| 关注层 | 端口可见性口径（沿用现有定义） | 「白名单层」 |
| 深探 | footprint 深度采样 | 「精确测量」 |
| 废纸篓 | 所有删除的去向 | 「删除」「清理掉」（按钮文案） |

### 7.2 措辞红线

- 数字：禁绝对化（「永远」「一定」仅可用于已证事实描述，如「永远加载不了」有实测依据）；估算值标 `≈`；口径必须可 hover。
- 空值：`0` 与「读不到」是两件事，绝不允许用 0 冒充。
- 破坏性操作：按钮文案必须暴露真实去向（`移入废纸篓` 而非 `一键清理`）。
- 泄漏判定：只说「疑似 / 嫌疑」，禁「确认泄漏」。

| 应用 · 磁盘三层 | `本体 2.1G / 缓存 1.3G / 数据 0.9G` | 同数字 + StackBar（三段） | 缓存占比 |
| 内存 · 概况 | `swap 已用 93%`（仅颜色区分） | MeterBar + 75/90 刻度线 + `14.0 / 15.0 GB` | 距危险多远 |
| 内存 · 详情内存构成 | 三行 CompareBar（各自的 max） | 顶部加 StackBar：`footprint 3.4 GB = RSS 0.1 + 换出 3.3` | 「97% 在磁盘」一个条说清 |
| 存储 · 分级 | 四行 `L1 7.74 / L2 22.5 / L3 21.7 / L4 3.0 GB` | 全量 StackBar + 每级行内 MeterBar + 「浪费 vs 可用」8.3:1 双段条 | 分级是否真分级 |
| 网络 · 网卡分布 | `en0 3.1 MB/s / en5 0.5 MB/s / utun3 0.1` | BarList（占比条 + 数值 + 虚拟口单列） | 哪块网卡在吃 |
| 网络 · 按应用 | 行内速率文本 Top 8 | BarList（速率条，上限 40% 宽） | 量级差 |
| 网络 · 诊断 | `23.4 ms / 8.1 ms / 128 ms` + 文字结论 | ThresholdBar ×3（阈值线 50/30/100，超阈变色）+ 结论行 | 哪一跳超、超多少 |
| 网络 · 测速 | `↓512 Mbps ↑128 Mbps` + `RPM 820` | MeterBar（对 1 Gbps 参考）+ RPM 刻度条 | 离满速差多远 |
| 端口 | 分组标题只有文字 | 分组头 StackBar + 组内计数 | 分组占比 |
| 菜单栏面板 | 六行数字 | 每行右侧 3 px mini 条（对各自参考值） | 不点开也知量级 |
| 灵动岛 | `96 %` / `换出破阈值` | 读数右侧 4 px mini 条（对阈值） | 超阈值多少 |

**改造纪律**：① 图与数字必须成对出现，图不替代精确值；② 不加新采样，全部前端派生；③ 无数据不画零条；④ 一页色阶 ≤ 2。
