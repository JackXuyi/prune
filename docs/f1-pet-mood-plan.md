# M20 机器宠物：小猫健康状态机（F1）方案

> 小猫皮从「只会按 CPU 快慢跳」升级为「表情随机器健康变化」：
> 悠闲 / 狂奔 / 喘气 / 炸毛四态，数据全部来自已有读数，零新权限。

## 一、背景与目标

**背景**：M22 小猫皮已把「CPU 忙闲」编码成跳跃频率（闲 5.8 s 一跃 / 满载 0.52 s 一跃），
但机器健康的另外两个维度——**内存紧张**与**磁盘将满**——完全不可见，要看面板才知道。
猫是程序化生成的（`scripts/gen-tray-cat.mjs`：SVG 姿态参数 → sharp → PNG），
新姿态可以量产，边际成本低。

**目标**：宠物状态 = 机器健康。不打开面板，瞄一眼猫就知道机器现在的处境。

**成功标准**：

| # | 标准 |
|---|------|
| S1 | swap 高危 / 内核压力 Warning+ 持续 30 s → 猫趴下喘气（新帧集） |
| S2 | home 卷剩余 < 10% 持续 60 s → 猫弓背炸毛（新帧集） |
| S3 | CPU EMA ≥ 85% 持续 10 s → 狂奔（现有帧集最快档，43–52 ms/帧） |
| S4 | 状态切换有迟滞，不抖动：喘气要持续平静 15 s 才恢复，狂奔掉到 75% 以下才收 |
| S5 | 多状态并发时有明确优先级：喘气 > 狂奔 > 炸毛 > 悠闲 |
| S6 | 剪刀皮行为完全不变；CPU 动画开关仍一键关闭所有动画 |
| S7 | `cargo test` 全绿（状态机单测 + 帧资源可解码断言）+ 生成脚本可重跑 |

## 二、不做什么（本期边界）

- **不做进化形态**（坚持一周不暴走 → 新形态）：状态机跑稳后再立项
- 不做新皮肤：剪刀皮维持原样（它不是宠物，表情没有叙事）
- 不加设置项：状态机随「CPU 动画」开关走，不加独立开关
- 不改岛：宠物表达在菜单栏，灵动岛事件通道（M15/M19）不受影响

## 三、方案

### 3.1 状态机（prune-core，纯逻辑可单测）

新模块 `crates/prune-core/src/pet.rs`：

```
PetMood: Leisure | Sprint | Pant | Alert

PetMoodMachine::observe(now_ms, cpu, swap_ratio_pct, pressure, disk_free_ratio) -> PetMood

| 状态 | 进入条件（连续保持）         | 退出条件（连续保持）        | 滞回线 |
|------|------------------------------|-----------------------------|--------|
| 喘气 | swap ≥80% 或压力 Warning+    | swap <70% 且压力 Normal     | 30s 进 / 15s 出 |
| 狂奔 | CPU EMA ≥85%                 | CPU <75%                    | 10s 进 / 10s 出 |
| 炸毛 | home 卷剩余 ≤10%             | 剩余 >12%                   | 60s 进 / 30s 出 |
| 悠闲 | 以上皆不满足                 | —                           | —      |
```

- **连续计时语义与 MemMonitor 同型**：中途一拍掉线就清零重来（偶发抖动不该累积成「持续」）
- **优先级裁决每拍重算**：喘气 > 狂奔 > 炸毛 > 悠闲（内存危机最紧急；CPU 高是「正在卖力」，
  比慢性的磁盘将满更有即时信息量）
- **读不到不冒充**：swap / 压力 / 磁盘任一传 None，对应通道安静跳过（不会拿 0 误判「充裕」）
- 数据源全部现成：CPU 用 tray.rs 的 1 Hz EMA；swap 走 `swap::read_swapusage`；
  压力走 `mem::system::read_pressure`；磁盘走 `disk::volume_info(home)`（statvfs，µs 级）

### 3.2 帧资产（生成脚本，可重跑）

新脚本 `scripts/gen-tray-cat-moods.mjs`（自包含，复用 gen-tray-cat.mjs 的几何助手风格）：

| 帧集 | 帧数 | 姿态 | 节奏 |
|------|------|------|------|
| `pant` 趴下喘气 | 4 | 身体压平贴地、四肢收拢、抬头张望；腹式呼吸 = 躯干 ry 振荡 | ~250 ms/帧（1 s 一次呼吸循环） |
| `arch` 弓背炸毛 | 4 | 万圣节弓背：躯干上拱（rot −20°）、头压低、尾巴竖直微摆、原地小幅起伏 | ~480 ms/帧 |

- 输出 `src-tauri/icons/tray-anim/cat-mood/{pant,arch}/{macos,win}/f0..3.png`
- 尺寸与主帧集一致（macos 64×48 模板图 / win 44×33 #34D399），眼睛镂空、圆润优先等纪律不变
- **狂奔不新增帧**：现有 12 帧前跃在 ≥85% 时已是 0.52 s 一跃的连续扑跳，视觉上就是狂奔

### 3.3 播放（tray.rs）

- `run_cpu_watch`（1 Hz）扩展为「宠物状态观察」：同一拍喂入 CPU EMA + swap + 压力
  （磁盘每 10 拍读一次），驱动 `PetMoodMachine`，结果存 `MOOD: AtomicU8`
- `run_anim` 增加心情中断：内层循环每拍检查 mood，变了就 break 重开（与换皮肤同一机制）；
  换心情时置 `LAST_FRAME = FRAME_DIRTY`（同索引不同帧集，必须真发一次）
- 帧集解析：Cat 皮 + Pant/Alert → 心情帧集；其余 → 原帧集 + `anim_beat_ms(CPU)` 原节奏
- tooltip 非悠闲时追加心情词：`Prune · CPU 12% · 喘气`（剪刀皮不加——它不是宠物）
- `anim_beat_ms` 对 Pant/Alert 不生效（心情帧集自带固定节奏）

## 四、里程碑拆解

| # | 内容 | 验收 |
|---|------|------|
| T1 | prune-core：`pet.rs` 状态机 + 单测（进入/退出滞回、优先级、None 跳过） | `cargo test -p prune-core pet` |
| T2 | 资产：`gen-tray-cat-moods.mjs` 生成 16 张 PNG | 脚本可重跑、尺寸一致 |
| T3 | tray：watcher 扩展 + run_anim 心情中断 + 帧集解析 + tooltip | `cargo check` + 帧解码测试 |
| T4 | 实测：压测 CPU / 塞满磁盘 / 大内存占用，观察四态切换与迟滞 | 手工验证记录 |

## 五、风险与对策

| 风险 | 对策 |
|------|------|
| 新姿态 18pt 下不可读（糊成黑块） | 沿用已验证的圆润纪律（贝塞尔圆耳、脚掌椭圆）；姿态差异靠**轮廓剪影**（趴/拱）而非细节表情 |
| 状态抖动（临界值来回横跳） | 全通道双滞回 + 连续计时；单测覆盖「卡在阈值附近不抖」 |
| 磁盘读数每秒 statvfs 开销 | µs 级系统调用，且每 10 拍才读一次 |
| 用户嫌猫「变了」不可解释 | tooltip 心情词是可发现性出口；方案文档 + changelog 写明触发条件 |
| 与 CPU 动画开关冲突 | 关开关 = 回静态原图，心情机照跑但不上屏（零成本） |
