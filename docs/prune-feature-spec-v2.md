## 0. 结论先行

| # | 结论 |
|---|---|
| 1 | **定位：开发机资源守门员**，不做内存监控、不做系统清理 |
| 2 | **杀手功能是磁盘侧 L1「跨平台二进制探测」** —— 零判断、零风险、数字震撼（本机实测 7.74 GB） |

## 1. 实测地基（方案中所有数字均来自真实采样）

### 1.1 磁盘侧（2026-10-22 扫描，只读）

| 项 | 实测值 |
|---|---|
| 机器磁盘 | 460 GB / 已用 319 GB（78%）/ 可用 92 GB |
| **可回收合计** | **54.85 GB** |
| 🟢 L1 跨平台二进制 | 7.74 GB（浪费比 8.3 : 1） |
| 🟢 L2 其余缓存 | 22.47 GB |
| 🟡 L3 需判断项 | 21.69 GB |
| 🔴 L4 Docker VM | 2.95 GB |
| 三包管理器重复 | npm 7.87 + Yarn 14.29 + pnpm 7.09 = **29.25 GB（占 53%）** |
| DerivedData | **仅 68 MB** ← 推翻「Xcode 是头号垃圾」的直觉 |
| JS 生态合计 | 46.2 GB（占可回收 84%） |

L1 细节：Yarn 缓存 6155 条目中 334 个为跨平台二进制（linux 196 / win32 74 / android 25 / darwin-x64 若干），而本机真正能加载的 `darwin-arm64` 仅 0.93 GB。`@next/swc` 一个包族缓存了 **25 个版本×平台组合**（单个体积 180~198 MB），实际只需 3 个。

### 1.2 内存侧（2026-10-22 采样）

| 项 | 实测值 |
|---|---|
| 物理内存 | 16 GB，空闲页仅 79 MB |
| Swap 已用 | 14.04 GB（上限 15 GB，已达 93%） |
| 被压缩内存 | 7.22 GB |
| 累计换入/换出 | 42.1M / 49.4M 次（持续颠簸） |
| **口径陷阱** | next-server 真实 3.35 GB → Activity Monitor 只显示 **113 MB**（97% 已被换出） |
| 同上 | tsserver 2.42 GB → 9 MB；meetily followup 1.77 GB → 51 MB |
| 最大常住户 | Cursor 全家桶 67 进程 / 4.26 GB（多窗口 extension-host 各 70~90 MB） |

### 1.3 桥：swap 是内存问题在磁盘上的投影

`/System/Volumes/VM/` 下 **16 个 × 1 GB swapfile**，3 天内累积（10-19 起 4 个 → 10-21 共 10 个 → 当天新增 6 个）。

三层含义：**①** 92 GB 可用里 16 GB 已被 swap 占用；**②** swap 逼近上限，再涨即 OOM 杀进程（表现为应用莫名闪退）；**③** 磁盘清理不止是"整洁"，是给内存系统留逃生通道。

## 2. 产品定位

### 2.1 边界（写死，不越界）

| 做 | 不做 |
|---|---|
| 开发环境可再生资源的探测与回收 | 通用硬件监控（打不过 iStat / Stats） |
| 内存真实占用口径与 swap 压力 | 内存清理 / 释放提速（伪科学） |
| 泄漏嫌疑判定（概率 + 克制措辞） | 全盘扫描、用户文档、照片去重 |
| 只碰白名单内的可再生路径 | 任何不在白名单的删除 |
| 端口反查（谁占着 3000 / 属于哪个项目） | 防火墙、抓包、流量监控（不是网络工具） |
| 应用维度资源卡（进程/内存/CPU/端口/连接/磁盘一次看全，磁盘数据层只读） | 按域名/对端拆分流量、累计流量统计（只做 1 s 差分速率）、跨应用磁盘清理（归属做不到精确就是错） |
| 统计总览（默认页）：内存 / 硬盘大小 + CPU 百分比 + 端口数量，只读 + 仅导航 | 通用硬件监控面板、任意指标的时间序列图表（只保留 CPU 10 min 走势）、在统计页放清理/结束进程入口 |
| 应用资源 tab：每应用一张卡（进程/CPU/内存/磁盘/端口/连接/网速），默认 Top 12，六字段排序 | 按域名/对端拆流量、Windows 按进程网速（要 ETW 实时会话）、跨应用磁盘清理 |

### 2.2 与四类竞品的错位

| 象限 | 玩家 | 态度 |
|---|---|---|
| 内存监控 | MPM（免费 MIT）/ Vitals / iStat / Stats | **不正面竞争**，只做它们的口径盲区 |
| 进程画像 | ProcXray | 不竞争 |
| 系统清理 | CleanMyMac / 腾讯电脑管家 | **划清界限**，形象反面 |
| 开发环境回收 | **无** | **主战场** |

### 3.1 菜单栏首屏的设计决策（关键）

Portlivo 的菜单栏首屏是服务列表；iStat/Stats/MPM 是内存百分比或压力。**Prune 的首屏主数字是「可回收 GB」**，理由：

- 内存百分比是**描述性**的（87% 已用 → 然后呢？）；可回收 GB 是**可行动**的
- 数字会随时间变化（新装依赖就涨），天然产生回访理由
- 这是唯一没人占的位

内存压力降级为右上角小圆点：正常时绿色不打扰，异常时才展开横幅。

## 5. 杀手功能详设：A1 跨平台二进制探测

### 5.1 检测逻辑

```
输入：缓存根目录（npm ~/.npm/_cacache、Yarn ~/Library/Caches/Yarn/v6、pnpm ~/Library/pnpm/store）
     本机架构 arch = uname -m（arm64 / x86_64）
     Rosetta 状态 = 是否安装

对每条缓存条目解析包名：
  提取平台标识 → linux | win32 | win | android | musl | freebsd | darwin-x64 | darwin-arm64
  判定：
    - 含 linux/win32/win/android/musl/freebsd  → 🟢 本机永远加载不了
    - darwin-x64 且 arch=arm64 且无 Rosetta    → 🟢
    - darwin-x64 且 arch=arm64 且已有 Rosetta  → 🟡 降级（x86 进程可能需要）
    - darwin-arm64 且 arch=arm64               → 保留
输出：条目数、总体积、按平台分布、Top 10 体积包
```

### 5.2 界面文案（照抄实测口径）

```
🟢 7.74 GB · 你的 Mac 永远加载不了

334 个跨平台二进制缓存包
  linux      196 个   4.1 GB
  win32       74 个   2.3 GB
  android     25 个   0.8 GB
  darwin-x64  39 个   0.5 GB

本机真正能用的 darwin-arm64：0.93 GB
浪费比 8.3 : 1

最大的一个：@next/swc 缓存了 25 个版本×平台组合
（单个 180~198 MB，你只需要 3 个）

              [ 查看清单 ]  [ 清理 7.74 GB ]
```

### 5.3 为什么它是杀手功能

| 维度 | 表现 |
|---|---|
| **零判断成本** | 用户不需要理解任何东西就能同意删除 |
| **零误删风险** | arm64 进程不可能加载 linux 二进制；且是缓存，删了会重下 |
| **数字震撼** | 7.74 GB / 8.3:1 —— 可传播 |
| **技术门槛低** | 纯文件扫描 + 字符串匹配，无权限问题、无 API 风险 |
| **竞品零覆盖** | 系统监控工具不碰磁盘，清理工具不认识包管理器缓存 |

> 这是整个方案里**唯一一个同时满足「零风险 + 零判断 + 强数字 + 无竞争」的功能**，必须置于首屏顶位。

## 6. 泄漏嫌疑判定（B5，沿用并修正 PRD §5）

### 6.1 关键修正

原 PRD 用 RSS 序列。**实测证明这不够**——next-server 真实 3.35 GB 但 RSS 仅 113 MB。判定必须基于 **`phys_footprint` 序列**（含换出部分），否则会漏掉全部被换出的进程，而它们恰恰是最该被标记的。

### 6.2 判定条件（全部满足才标记）

```
存在时长 > 30 min
且 近 30 min 净增长 > 150 MB 且 > 40%
且 线性回归斜率 > 0 且 R² > 0.70
且 不在良性名单（Chrome / Electron / VM / 系统进程）
且 若为 GC 语言（Node/Java/Go）→ 门槛翻倍至 300 MB / 60 min
```

### 6.3 措辞硬约束（继承 PRD，与 MPM 一致）

- 永远说「疑似内存泄漏」，**永远不说**「你的 XX 泄漏了」
- 必须展示依据：增长量 + 时长 + 曲线
- 概率判定，**误报一次的信任成本远高于漏报一次**

## 7. 安全分级模型（动工前定死，不能事后补）

### 7.1 四级分类

| 级别 | 判定标准 | 交互 |
|---|---|---|
| 🟢 L1 | 本机架构永远加载不了 / 包管理器缓存 | 一键清理，无二次确认 |
| 🟢 L2 | Homebrew / Cargo / DerivedData / 其余可再生缓存 | 一键清理 |
| 🟡 L3 | 项目 node_modules / Simulator / Playwright | 展示「上次改动 N 天前」，逐个确认 |
| 🔴 L4 | Docker 卷镜像 / iCloud 本地副本 / 任何白名单外路径 | **只输出命令，不执行** |

### 7.2 代码层硬护栏（不是提示，是约束）

1. **路径白名单**：只删除预定义的可再生缓存路径，不接受用户自由输入路径
2. **禁止递归 rm**：不实现任何形式的递归删除用户目录
3. **废纸篓而非 rm**：所有删除走 `Trash`，可恢复
4. **Dry-run 前置**：首次执行先列出前 20 项供确认
5. **总量熔断**：单次删除 > 20 GB 时强制二次确认（即使 🟢 级）
6. **无提升权限**：永不请求 root / 全盘访问；拿不到的就不做

## 8. 技术方案

| 层 | 选型 | 备注 |
|---|---|---|
| UI | SwiftUI + `MenuBarExtra`（macOS 13+） | 与 Portlivo 同栈，零学习成本 |
| 磁盘扫描 | `FileManager` + 后台队列 + 深度上限 | 复用已有 `reclaim-scan.sh` 逻辑 |
| 内存 | `proc_pidinfo` / `task_for_pid` + `task_info(TASK_VM_INFO)` | **需 M0 验证**（§10） |
| 系统压力 | `host_statistics64(HOST_VM_INFO64)` | 公开 API，无权限 |
| 历史 | SQLite（footprint 时间序列） | 供 B5 回归计算 |
| CLI | `prune`（ArgumentParser） | 与 MPM 对齐 |
| 更新 | Sparkle | |
| 自启 | `SMAppService` | |
| 隐私 | 零埋点、零遥测、无网络请求（除更新检查） | 营销资产 |

**沿用 Portlivo 的可复用资产**：IA 三段式（菜单栏/主窗口/检视器）、进程画像（`KERN_PROCARGS2` + PPID 上溯）、键盘优先 + ⌘K、SwiftUI+SMAppService+Sparkle 技术栈。
**明确不适用**：HTTP 健康探针、实时日志、QR 码、公网隧道。

## 9. 决策点（需逐条确认后再实施）

| ID | 决策 | 我的建议 |
|---|---|---|
| **D1** | 双模块还是单模块 | **双模块**。但磁盘为主、内存为辅；内存只做 B1/B2/B4 三个盲区，不做通用监控 |
| **D2** | 产品名 | **Prune**（开发者秒懂 `npm prune` / `docker prune`，动词、短、好记）；Footprint 已不贴切 |
| **D3** | 首发顺序 | **磁盘优先**。A1 零风险零判断，是验证 PMF 最快的路径；内存模块依赖 M0 验证结果 |
| **D4** | 是否做一键清理 | **做，但仅限 🟢/🟡**。若只探测不执行，价值减半、用户会自己 `rm -rf` 反而更危险 |
| **D5** | L4 Docker 是否做 | **M3 再说**，且永远只给命令。Docker 误删代价最高 |
| **D6** | 定价 | **$12 一次性**，免费版限制为「可探测不可清理」。或参照 Vitals 首发 $9 冲量 |
| **D7** | 是否开源 | **不开源**（MPM 是 MIT 免费，开源等于放弃商业化）；但公开扫描路径白名单以建立信任 |

## 10. M0 必办验证（动工前，按重要性排序）

| # | 验证项 | 判定标准 | 影响 |
|---|---|---|---|
| 1 | 非特权下 `task_for_pid` + `task_info(TASK_VM_INFO)` 是否成立 | 30 行 CLI，能否读到他人进程的 `phys_footprint` | **决定 B1 走哪条路**。失败则退回 RSS 口径，B1 的差异化消失 |
| 2 | 磁盘扫描性能 | 6336 个 node_modules 全量扫描耗时 | 决定增量策略（已知教训：逐个 `du` 会被 kill，须 `xargs -0 -n 300` 批处理） |
| 3 | swap 指标可读性 | 与 Activity Monitor 对照偏差 < 10% | 读数不对信任就崩 |
| 4 | A1 跨平台识别准确率 | 在 3 台不同架构机器上抽样 100 条人工核对 | 误判为"无用"而删除 = 严重事故 |

> **#1 是生死线**：若拿不到 `phys_footprint`，内存模块的核心卖点（口径真相）不成立，**应当立刻收敛为纯磁盘产品**，而非硬做。

## 12. 风险清单

| 风险 | 等级 | 应对 |
|---|---|---|
| 删除造成不可逆损失 | 🔴 | 废纸篓 + 白名单 + 熔断 + 无提权（§7.2） |
