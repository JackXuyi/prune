## 三、核心结论（≤200 字）

Prune 的「可引用事实资产」密度高（一句话定位、带时点实测数字表、六条代码层护栏、8 个只读 MCP 工具），且已有文档诚信门禁——底子在同类开源里属上游。但三个结构性短板决定当前 GEO 基本盘：①公开面滞后——v0.9.4/v0.10.0 的提交已推送，但两个 tag 未打，CI 从未出包，公开 Release 面停在 v0.9.3；②信源全孤证——零 FAQ、零 JSON-LD、零英文版、零第三方印证；③门禁有假阴性——白名单 68↔84 漂移、排他 sweep 两处逃逸、无 push/PR 日常 CI。优先级：打 tag 让公开面对齐 → 落地 FAQ/JSON-LD/修漂移 → 补门禁 → 首测。

## 四、分阶段执行方案与关键产出（D→S→G→M）

### D 阶段 · 现状诊断（查分明）

- **优势**：README 首屏即「AI 引擎最易直接引用」的事实形态——一句话定位 + 三件实测事实（7.74 GB 跨平台二进制/浪费比 8.3:1、29.25 GB 三包管理器重复、RSS 113 MB↔footprint 3432 MB）；六条安全护栏全部是代码层约束；`check-docs-honesty` 对 MCP 工具清单做三方对账。
- **准确性风险**：ad-hoc 签名三处文档口径不一（「ad-hoc 签名」vs「未签名」、`xattr -dr` vs `-cr`）；RSS/footprint 双口径缺面向外部读者的解释段；旧档案残留失效排他表述（roadmap-2026-11:151、spec-v2:213）；版本徽章检查承诺未兑现。
- **缺口**：无英文版、无官网、无 FAQ、无 JSON-LD、零第三方印证；核心数字 n=1 单机样本，内容须带时点语境。

### 分发阶段 · 信源与分发（袁通达）

- **三级信源**：一级（自有可控）= GitHub canonical + Gitee 纯镜像（同一 commit 双推，不造第二套元数据）；二级（自建）= docs/faq.md、技术说明、JSON-LD 块 A、Homebrew cask（只讲路径不讲结果）、英文 README；三级（外部印证）= 社区原创首发（单渠道首发、一稿多发只算一个信源）、包管理器收录、评测站（只能被引来，提供可复现实测方法）。补齐顺序必须 1→2→3。
- **交叉验证矩阵**：MCP 8 工具（已门禁）、只读底线（双重覆盖）为防护最好事实；**无门禁敞口** = 白名单计数、README 版本徽章、实测数字多载体引用、双源 README hash。修复前任何分发文案禁用「N 条白名单」表述。

### M 阶段 · 引用监测（蔡真准）

- **四层指标**：L1 信息准确性（FACR/FCC/高危错误 HE 绝对值恒零目标/数字保真 NCF/定位保真）、L2 引用准确率（引用率 CR/canonical 指向率 CAR——Gitee「正确但次优」单列/引用一致率 QCR/信源域名分布）、L3 可见性（提及率只记录不归因、形态分布、语料陈旧度、竞品并列计数）、L4 基础设施健康度（六项可全自动）。**硬口径：不用排名/首位指标**——生成式答案无稳定名次、不可归因、会诱导优化错误目标。
- **九条核心事实基线**（L1 判定唯一标准）：定位（显式否定内存监控/系统清理）、平台（Windows 必须带 beta）、MIT、v0.10.0、7.74 GB、29.25 GB、113↔3432 MB、MCP 8 只读无执行通道（权重极高）、白名单 68 条。F9 特例：漂移修好前，AI 说 68 或 84 都能在仓库找到出处——属「仓库自相矛盾」必错项，先修代码侧，此期间不计入 FACR。
- **首测方案**：16 条查询集（Q-B1~B4 品牌词 + Q-01~Q-12 场景词，待与 G 阶段原文 1:1 对齐措辞）× 六平台 × 2 采样；SIM/API 分开统计；联网开关、登录态、会话卫生等采样口径全部显式记录。**诚实定位：首测是「分发动作落地后的基线」，不是改造前零基线，不能用来证明改造收益**——必须在 D+3 动作生效后跑。
- **L4 本地实测快照**（本次唯一实跑数据）：L4-1 版本四处一致 ✅ / L4-2 计数 68↔84 ❌ / L4-3 门禁绿但假阴性 ⚠️ / L4-4 公开面停在 v0.9.3 ❌ / L4-5 双源一致 ✅ / L4-7 未推提交 1 个 ⚠️。
- **复测判读**：判改善需三条件同时满足（多采样多数一致 + 方向属四类指标 + 其它单元无同向变化）；提及率下降不判退化；同会话连问不算独立样本。节点 T0(D+3)→T1(D+14)→T2(D+30)→T3+(月度)+事件驱动。
