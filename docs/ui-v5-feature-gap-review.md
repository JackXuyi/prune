# UI v5 原型 × 现有应用 功能覆盖度评审

> 评审对象：`docs/ui-v5-prototype.html`（Quiet Cockpit v5 概念稿）
> 基准：现有应用真实功能面（MainWindow 6 tab + 面板/灵动岛/托盘 + M19–M25 全部落地功能）
> 日期：2026-11-11 · 评审人：UI Designer

## 结论先行

**原型当前是「清理工具」的概念稿，但 Prune 实际是「资源驾驶舱 + 清理」。**
原型覆盖了 6 个真实 tab 中的 3 个（总览/存储/网络的骨架），遗漏了整整两个一级 tab（应用、内存），
且清理流与真实 IA 的归属有偏差。概念稿可作为视觉语言提案，**不可直接作为 v5 实施蓝图**。

覆盖度速览：

| 原型板块 | 对应真实功能 | 覆盖判定 |
|---|---|---|
| 概览（磁盘环 + NBA + 4 域卡） | 总览 stats：可回收主卡 + 成绩单 + 六域卡 | 部分覆盖 |
| 清理（三态流） | 存储 tab ReclaimBoard | 部分覆盖 |
| 网络（LAN 卡 + 吞吐双线） | 网络 tab 监测页 + 端口页 LanBoard | 骨架级 |
| 端口（表格 + 异常徽标） | 端口 tab PortBoard | 骨架级 |
| 统计（7 日柱 + 构成） | 总览成绩单 + 统计 | 骨架级 |
| 设置（开关组） | SettingsBoard 弹层 | 部分虚构，见 P2-4 |
| —— | 应用 tab（AppResourceGrid + AppDetail） | ❌ 完全遗漏 |
| —— | 内存 tab（家族列表 + 泄漏侦探 + 进程详情） | ❌ 完全遗漏 |
| —— | 菜单栏面板 / 灵动岛 / 托盘宠物 | ❌ 未体现 |

## P0 — 一级功能遗漏（不做则原型失真）

### P0-1 「应用」tab 整体缺失
- 真实功能：AppResourceGrid 按进程家族聚合的资源卡（内存 / 磁盘本体 / 按进程网速 nettop / 端口徽标）→ 点卡下钻 AppDetail（HistoryTrack 24h/7d/30d 历史走势、ProcTable 进程表、ResourceTile、跳端口、跳进程）
- 原型现状：无任何对应物，Rail 里没有这个入口
- 设计建议：资源卡网格 + 「点卡下钻」是本产品信息架构的关键路径，v5 必须保留「列表 → 详情 → 返回」模式

### P0-2 「内存」tab 整体缺失
- 真实功能：家族列表（展开进程、工作区归属徽标）+ 内存概况（压力环、swap 阈值渐变条、换出受害者列表）+ ProcessInspector（构成堆叠条 footprint=RSS+换出、监听端口徽标、4h 走势）+ LeakCard 泄漏侦探卷宗（案件编号、证物曲线、档案室）
- 原型现状：只有一张 MEM 域卡显示 8.2/16 GB
- 设计建议：内存是 Prune 的差异化重头（phys_footprint 口径 + 换出受害者 + 泄漏侦探均为竞品独有点），v5 若砍掉等于自废武功

### P0-3 「结束进程」交互缺失
- 真实功能：内存/端口/应用三处右键 → 两步确认菜单（结束 SIGTERM / 强制结束 SIGKILL，含后果说明文案）
- 原型现状：无任何进程级操作
- 设计建议：这是驾驶舱类产品的核心动作，原型至少要在内存/端口板演示「右键 → 两步确认」流

### P0-4 导航结构与真实 IA 偏差
- 真实 IA：6 tab = 总览 / 应用 / 内存 / 存储 / 网络 / 端口；设置是标题栏齿轮弹层，不占一级导航
- 原型 IA：概览 / 清理 / 网络 / 端口 / 统计 / 设置 —— 「清理」独立成 tab（真实中清理属存储 tab），「统计」与「概览」职能重叠，设置占了本应属于「应用」或「内存」的坑位
- 设计建议：对齐真实 6 tab；清理流收进「存储」，NBA 卡的「去清理」直接跳存储 tab（现有 `goBoard('re')` 改 `goBoard('disk')`）

## P1 — 重要功能遗漏（影响完整性与差异化）

| # | 遗漏项 | 真实功能 | 建议 |
|---|---|---|---|
| P1-1 | 网络诊断二级页 | NetBoard 监测/诊断双二级页，分层探测图表化 + 报告复制 | 网络板加「监测/诊断」页内切换 |
| P1-2 | 剪除成绩单 | 累计回收 GB（CountUp）+ 换算彩蛋（电影 4GB/照片 3MB）+ Top 3 + 空态引导 | 放进总览或统计板，这是情感化设计的招牌 |

## P2 — 体验层遗漏（v5 实施时补齐即可）

1. **快捷键系统**：⌘1–6 切 tab / ⌘R 刷新 / ⌘F 聚焦搜索 / Escape 关弹层——原型未体现，实施时是硬性验收项
2. **下钻返回**：所有跨页跳转必须显示「← 返回{来源}」（UX v3 §4.2），原型 NBA 卡跳清理没有返回路径
3. **搜索**：应用/内存列表均有搜索框（⌘F 聚焦），原型无
4. **设置项与虚构偏差**：原型里的「每周自动扫描」「低空间预警」是**虚构的**（真实设置板没有这两项）；真实设置含端口冲突保镖 / 局域网新面孔 / 宠物开关 / 语言切换 / 明暗主题。需决策：砍掉虚构项，或作为新功能提案单独立项
5. **刷新语义分流**：真实刷新按钮按 tab 显示「扫描中/扫描端口/采样中/刷新」四种状态文案，原型只有重扫
6. **空态设计**：EmptyArt 组件 + 「暂无可回收·看明细」「尚未深探」等文案红线，原型只有满数据态
7. **托盘宠物**：猫四态心情（悠闲/狂奔/喘气/炸毛）在托盘层，主窗原型可不画，但 v5 总体方案文档应收录

## 修订路线建议

**方案 A（推荐）：对齐真实 IA 修订原型**
1. Rail 改为真实 6 tab（总览/应用/内存/存储/网络/端口），设置移顶栏齿轮弹层
2. 清理三态流并入「存储」tab；NBA 卡改跳存储
3. 新增「应用」「内存」两板的骨架（家族卡网格 + 泄漏卷宗卡）
4. 全局补：口径徽标、返回路径、快捷键提示、空态

工作量约 1 轮修订（在现有单文件原型上迭代），修订后原型即可作为 v5 实施的视觉基准。

**方案 B：维持「清理优先」叙事并反向驱动产品**
若 v5 产品方向就是「把 Prune 从驾驶舱收敛为清理工具」，则需先做产品层决策（砍应用/内存 tab 是重大功能回退），不建议由 UI 层单方面决定。
