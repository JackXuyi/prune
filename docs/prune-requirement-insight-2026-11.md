## ⓪ 前置事实与统一原则（排在定价、锚点、工期之前）

### D0 · LICENSE 决策记录（第 0 行，必须先于一切拍板，不是欠账项）

**M26 的「补 LICENSE（MIT）」不是工程欠账，它是整个商业化的开关。** 它现在以 review P1-9（"公开发布法律前提"）的身份进表，看起来只是 1 行文件，但结论链条是：

`MIT → 功能 gate 不成立 → 分发成为唯一变量 → 锚点不可售 → 不做功能商业化`

一个 1 行提交决定了整条路线是否成立，而它进表的理由（法律前提）与它真正的功能（能否 gate）毫无关系——这是最典型的**工程表里藏战略决策**：它永远不会触发 review 关注，因为它看起来不像一个决策。synthesizer 另指出：红队砍得最顺的三条结论（gate 无效、分发唯一变量、锚点不可售）**全部挂在这根柱子上——这是全案的单点故障，必须是决策，不能是欠账。**

**处置**：M26 的 P1-9 改写为「LICENSE 待决策」，不写「补 MIT」，避免工程表替产品做决定。单列 D0 决策记录，两条分支后果：
- **选 MIT** → 放弃功能 gate → 走 B2 或便利费（$10–20 一次性，不是 $29）；
- **选 source-available** → 可 gate，但失去「代码可审计」这条叙事证据链 → **判定不可选**（拿唯一资产换约 $1–3K）。

拆出来的意义不在改结论，而在**让这个决定被显式做出，而不是被一次文档补齐顺手做掉**。决定化升级判据（两条同时满足才升级，否则每项都决策化会让表变成决策日志）：①执行结果不可逆；②表里的表述已预设了结论（「补 MIT」是在替你选，不是问你）。LICENSE 两条都满足 → D0；「加 CI 测试」两条都不满足 → 不升级。

**MIT 是成本结构，不只可信度**（推演师终局正向结论）：维护成本主要驱动是 AI 路径跟踪，而白名单本质是一个数据文件——结构简单、可独立验证 → 天然适合社区 PR；MIT 下年度维护从"12–24 天作者工作"降为"若干次审核"。且外部化是"纯赚"：**白名单从来就不是护城河**（CacheCleaner 已开源全部路径、DevCleaner 覆盖 30+ 生态），把一份本来就免费的东西送出去，不依赖社区是否活跃就已省下重复劳动。定稿句（带条件，防止被读成已成立的解药）：

> **MIT 的价值不只是可信度，它是这个项目的成本结构。选它不是为了开源，是为了活下来。**
> **——但社区先于它的收益，而社区来自分发。所以它不是解药，是把"独自承担"改成"有条件分担"。**

残余（不美化）：外部化**降边际成本，不减固定成本**——首发仍要一次性建全 30+ 工具链白名单（1–2 天），审 PR 是持续成本；准确表述是 MIT 把维护从"线性增长"变成"边际递减"，不是降到零。

**白名单外放规则（可加不可减，写进该文件文件头）**：社区 PR = 错误路径 + 错误分级 = 一次数据丢失事故是真的，但可按"能否用测试代替判断"划线——

| 允许 PR 修改 | 判据 | 结论 |
|---|---|---|
| 扫描路径条目 | 存在性可测 | 可 PR，**每条须自带断言测试** |
| 分级建议 🟢🟡🔴 | 规则可判定 | 可 PR，**须过护栏测试组才合并** |
| **硬拒绝清单（含会话/凭据）** | 无法证明"删掉也安全" | **可加不可减，永不接受删除 PR** |
| 探测/执行逻辑 | 不可判定 | 不外放 |

效果：把"审代码时间"大部分转成 CI 时间；事故面从"社区能破坏安全"缩到"社区能提议删除但需作者批准"。

### 统一原则：「不新增无法自证的商业陈述」＋三处边界修

四个「不」是同一条原则的应用（不 gate / 不划线 / 不遥测，举证责任在 gate 一侧——不可逆折损 vs 可逆收入的举证门槛不对称）。三处修正：

1. **Windows 不归此原则管辖，独立成条**——Windows 版的核心陈述（"这台机器上有 7GB 可删"）是可自证的，硬归进来会被一句话击穿；误归类的代价是将来有人用"Windows 的陈述可自证"绕过真正理由（见 §⑤）。
2. **新增方门槛更高 ≠ 现状免举证**——B2 也过不了可持续性这一关（Sponsors 每月几十到几百美元）。不写这句，原则会退化成"维持现状永远正确"。
3. **原则的日常价值 = 自检出存量文案硬伤**（见 §⑧ 清理清单），这比它筛掉的四件事更有用。正向确认：「零权限」「零遥测」「MIT 可审计」都是可自证的——**原则只砍不可自证的那一半，不伤真正的差异化。**

## ① 一句话理解

Prune 是**危机驱动的"安全删除保险"**：真需求成立但极窄。功能 gate 在 Prune 上**穷举后为空**（危机时刻可售物 = 已被免费赠送的集合）；买断制的结构性错误不是"总单量差一点"，而是**每年需要 110–210 单新增销售且必须每年重复**。终局结论：**不做功能商业化——不是"暂不商业化"（时间问题），是"以收入覆盖成本为目标在本量级不成立"（结构问题）；唯一紧急的事是免费发布与装机（获客窗口），唯一不紧急的事是商业化本身；其余全部等 D0 + R15。**

## ③ 真实痛点与三时刻错位

**四真问题**：①删了不会出事的确定性（命中，被侵蚀项见 §④）②AI 吞盘的控制权（部分命中）③"值多少"（未命中）④危机后遗忘断层（未命中）。

**三时刻错位**（商业结论的承重结构，三层各自独立、互不重叠）：

| 时刻 | 状态 | 可测指标 |
|---|---|---|
| 需求时刻（盘红）| 只想删除，无心做购买决策 | 盘占用率 |
| 决策时刻（首扫）| 大数字是惊讶不是危机，无痛感 | **首扫后 24h 内是否执行过一次清理** |
| 可售时刻（非危机批量管理）| 用户不在场（留存 2–4%）| 第 8 天回访率 |

**任一层改善都不足以翻案，必须三层同时被打破**；且三层数据全部依赖分发才能观测——观测本身是一笔支出（见 §⑤ 成本修正）。

**「提醒不是预防」必须条件化**：正确表述是「**在现有产品原则下**（人在回路、只读、不自动执行），Prune 最多只能交付提醒队列，提醒不是预防」——若未来真做出自动执行，此条立即失效。所有基于它的判断（锚点不可售、清单非预防）同样受此前提约束，否则它会变成一条"看起来永远成立"的教条。

**竞争证据修正**：Spookle（2026-10-24 上线）逐字产品化"AI 只读人执行"且更可感知——**情报流程失效确认，今后所有"X 仍无竞品"论断一律标"未经证实"**；RAMWatcher 追平 footprint 口径；免费克隆洗劫清理场景；DevCleaner 收费墙证据弱（安装 2,200+）。免费层矩阵：Prune Free 在清理广度上是 Spookle Free 的真子集（缺卸载残留/AI agent 幽灵清理/端口↔repo），在探测深度上是超集。

## ④ 结构化需求 · 定稿（15 条 + 覆盖修订）

### 功能 gate 穷举表（终局命题）

**「危机时刻可售物 = 已经被免费赠送的集合」**——危机时刻唯一有独家供给的东西（只有 Prune 能指出的跨平台二进制）已被免费赠送，收回它触发自家护栏。逐项穷举：跨平台二进制（已免费）/ 重复存储（已免费）/ footprint（已免费）/ AI 缓存（对手有）/ Xcode 深扫（对手有）/ 幽灵进程（Spookle 有）/ Docker 执行（定位红线）/ 归档（可逆性无定价承载力且 free 路径更快）→ **穷举后为空**。唯一未死的一行是 Windows（候选不是路线，见 §⑤）。

**可逆性不能作为付费理由（阈值型判定）**：付费意愿 ∝ 不可逆损失量级；node_modules 重装 5–20 秒/项 ≈ $0.1–1，远离阈值。**Prune 扫描的全部资源都是可重建的——专做可重建资源清理的产品，天生没有资格卖"可逆性保险"。** 这解释了为什么 Spookle/DevCleaner 的 Pro 卖自动化与广度、不卖安全。

### 文案红线 / Won't / 护栏

- **禁排他性句式**：禁「只有 Pro 才能批量归档」，也禁看似中性的「Pro 版支持批量归档」——一律描述句「官方构建提供批量归档 + 自动更新 + 支持」。
- **Won't 清单（终版）**：订阅/年费｜功能 gate（MIT 下无法自证）｜在线校验/设备指纹/解绑｜grandfathering（作废）｜预售页（卖假设）｜划线原价/假挂牌期/倒计时｜安装侧遥测｜🟡 转 Pro｜mtime 回溯估算｜"任何删除都需人确认"绝对断言｜treemap/卸载器/风扇/软件更新｜Windows 完整化路线（独立成条的条件句候选）｜MAS 上架｜source-available。
- **护栏两条**：①任何需求若需要 grandfathering ⇒ 正在收回既有能力，违反「只 gate 新增功能」，打回重设计；②禁排他性暗示、禁划线原价、禁倒计时同属**对价陈述失实**一类。

## ⑤ 推演与风险（定稿账）

### 买断制的结构性错误（终局最硬的数字）

维护成本现实 1–2 天/月 = **12–24 天/年 ≈ $4.8K–9.6K/年**（$400/工作日口径，与开局 $16K/8 周同源，无独立假设）。按 $46 净价：

> **覆盖维护每年需要 110–210 单新增销售，且必须每年重复。**

买断收入是一次性的，维护是年度的 → 它要求**每年都重新成功首发一次**。这解释了为什么"回本 230–360 单"一直让人觉得差一点——**差的不是总数，是年度复制能力，而那恰好等于分发能力**。

### 定稿句与 B2 的位置

> **在此量级没有任何商业化形态成立；B2 是唯一不新增风险的形态，同时它是一个公开承认自己不可持续的选择。**

防误读：**这不是「暂不商业化」（时间问题），是「以收入覆盖成本为目标在本量级不成立」（结构问题）**——两者导出完全不同的下一步（前者"过段时间再看"，后者"改变形态"）。B2 不能写成答案/解法：Prune 应明确写成**非商业项目**，存续来自作者非经济动机（作品集/能力证明/自用）+ 零星赞助——这是个人开源项目的常见合法形态，但若把 B2 写成解法，它就成了保守偏好的挡箭牌。

### 窗口分层与紧迫性

**定价窗口已死**（4–5 周工程 > Vitals storage map 1–3 个月窗口；MIT 下无 gate，无心智可卡——原 roadmap D2「晚收比早收难」整条删除）；**获客窗口活且升为第一优先**——理由从竞争改挂收入结构：gate 塌了 → 收入只剩 装机 × 转化，转化项整体塌陷 → **装机从瓶颈之一变成唯一变量**；即使 Vitals 明天放弃 storage map，获客仍是第一优先。**紧迫性分层**：紧急·现在做（0 工程）= 免费发 v0.9.1 + 落地页 A/B + 开 Sponsors；不紧急 = 4–5 周工程与商业化（等验证结果）。

### 观测成本修正（6–15 天，需单独批准）

「发布运营 3–5 天」只买**一次**读数；「触达可重复性」需 2–3 次事件 → **真实成本 6–15 天**，且是一笔需单独批准的支出。比值仍成立（验证 6–15 天 vs 建设 20–25 个工作日，便宜 3–5 倍），但绝对量不小。**翻案条件最终表述：「先批准并支付 6–15 天分发成本，再读三层数据；三层须同时被打破」。**

### M31 Windows（独立成条，三条理由 + 无上限成本）

红队撤回自己的"持续现金支出"论据（$300/年证书 ÷ $46 ≈ 6.5 单/年即可覆盖，不构成反对理由——**一条能被一句算术打掉的论据留在报告里，会让另外三条也显得可疑，弱论据污染强论据**）。Windows 的反对理由只剩三条硬的：①三个独家能力只有跨平台二进制可迁移，**footprint 无等价物 → "口径不撒谎"叙事在 Windows 版没有落地物**；②UAC 提权破"零权限"；③**稀缺可能反映需求不足而非供给空白**（Mole/DevCleaner/CacheCleaner 全在 macOS，既可读作"没发现"，也可读作"算过，不值得"）。成本项：另建 AI 路径跟踪 + 磁盘白名单 + updater 全未验证，**维护面 ≥50 个工作日、无上限**（未验证平台的估计分布右偏，无法给没做过的事算上限）——与"收缩维护面"真正冲突。**条件句**：「若 macOS 侧证明付费意愿存在，则 Windows 是唯一可迁移方向」；先在 macOS 证明，再谈移植，双重不确定不叠加。

### 对称偏差披露与红队用法（进正文，比判据更可执行）

- 方案作者因产出压力偏向「能落地」（撤回 9 条判断，多条是写死后才被打中）；评价者因不承担造价偏向「不做」（红队自陈错误集中发生在给出具体量时）。**两句并列，必须同时写。**
- **红队用法**：「红队在『不可取』这一层几乎不会错——因为错了也不被检验；在『具体量』这一层会错且可被检验。因此红队结论应当用于砍方案，不用于定量。」自检判据（"这个区分有没有改变明天要做的某个具体决定"）作为附注：**一个告诉你该信哪一层，一个告诉你自己是不是在找台阶。** 红队结论是筛选器，不是决策。

## ⑧ 文案治理：不可测试的句子（两类）+ 存量清理清单

**评审新类别：「不可测试的句子」**——共同点：写错不影响功能，只影响信任，测试与 CI 都抓不到，**不可外包给 CI**。判据："这句话如果为假，谁会发现、多久发现、代价是什么"。**按反馈机制拆两类**：

- **删除类（无任何反馈机制能纠正，直接不写，不给观察期）**：一切独家性/首创性声明——**独家性由竞品发现，而竞品没有动机告诉你**，实际等价于"不会被发现"（Spookle 那次正是外部情报而非内部流程发现的）。
- **观察类（能被发现，每次发布前逐句过）**：数字口径 / 永久性与更新承诺 / 退款与隐私承诺。

**存量清理清单（立规则同时清旧账）**：

| 现有文案 | 处理 |
|---|---|
| README/spec「无网络请求」 | **P0 独立热修**（唯一线上生效 + 法律暴露）|
| 「独家」「唯一」「首个」类表述（含"唯一把 AI 只读人执行写进代码层""跨平台二进制探测（独家）"）| **直接删除**或改为可核验事实陈述：「我们检测 X；竞品是否检测请自行验证」|
| 竞品对比表排他性措辞 | 一律「我们做／未做」，不写「只有我们」|
| 「lifetime / 永久」 | 改「**所购版本永久可用 + 1 年更新**」（两者均可自证）|
